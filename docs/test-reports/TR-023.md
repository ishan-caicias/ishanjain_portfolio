# TR-023 — Wireframe-Flash Regression on Page Load

**Date:** 2026-07-18
**Scope:** Owner manual regression: blank → gold wireframe → textured model on tab open
**Verdict: OVERALL: READY TO PROCEED**

## Validation of the Report

Two distinct observations, one verdict each:

1. **Blank first seconds — not a bug.** That window is the 168k-star catalog streaming to the
   GPU plus the GLB fetch, with the hero copy deliberately hidden by the F0 loading
   choreography (nav + HUD render immediately). Network-bound.
2. **Wireframe → textured swap — confirmed bug.** `_drawShip` fell back to the wireframe
   whenever `craft.ready` was false, _including while the GLB was still loading_. Correct at P1
   (flag-off; wireframe was the product), but a defect since the P5 default-on flip: every
   visitor saw the wrong ship first. Missed by earlier captures because local GLB loads beat
   the screenshot delays.

## Fix

`_drawShip` now draws **nothing** for the ship while a craft is expected but pending
(`craftTier !== "off" && !_craftFailed && !craft.ready`) — no wireframe flash, no orphaned
plume/glow — while flight state keeps integrating so the craft pops in at the settled pose.
New `_craftFailed` flag (set in the load catch, reset on retry) keeps the wireframe serving its
two real jobs: `?craft=off` opt-out and load-failure/old-browser fallback.
