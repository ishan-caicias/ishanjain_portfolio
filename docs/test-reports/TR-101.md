## Change

One-line addition to `SpaceScene.tsx`'s existing import chain — `celestial-content-overlay-ngc2000.js`
now loads via its own `.then()`, chained immediately after batch 1's overlay
(`celestial-content-overlay.js`) and before `setEngineReady(true)`. Same reasoning as batch 1's
own sequencing comment: `Promise.all` gives no ordering guarantee across its array's own
top-level module side effects, and each overlay's entire job is overriding ids the earlier
catalog modules add, so each must run strictly after every catalog module has already run —
chaining the two overlays as separate `.then()`s (rather than one combined import) keeps that
guarantee for both.

No other production code changed. Header comments in `celestial-content-overlay-ngc2000.js`,
its unit test, and the source-list analysis doc were updated from "staged, not yet wired" to
reflect the approval and wiring (documentation-only, not a behavioural change).

+9.6 KB gz over TR-100's measurement (1191.3 → 1200.9 KB) for 41 real field-notes + lore
entries — consistent with batch 1's own +4.6 KB for 25 entries (roughly proportional per-entry

(1205 vs. 1200.9), not a round-number jump — this repo's budgets "ratchet down when the payload
shrinks and are only ever raised deliberately, with a comment and a TR reference"
