## What shipped

**D5.2 — Search v2.** New pure module `src/lib/destination-search.ts`: ranked matching
(exact-name > id/designation > name-prefix > word-start > substring, stations outranking
bodies/classes at an equal tier), id/designation normalisation (`ngc7293` finds `NGC 7293`),
an empty-query "NOTABLE DESTINATIONS" featured list (`FEATURED_DESTINATION_IDS`, resolved from
the live index so it can never drift from the catalog it names), and `totalMatches` for honest
truncation (`N MATCHES · SHOWING 10`). `MissionControlBar.tsx` rewritten as a real ARIA
combobox: `role="combobox"`/`aria-expanded`/`aria-controls`/`aria-activedescendant` on the
input, `role="listbox"`/`role="option"` on the dropdown, Arrow Up/Down/Enter/Escape owned
locally. The suggestion dropdown now opens **upward** (`bottom-[calc(100%+8px)]`, was
`top-[calc(100%+8px)]`) — the mission bar is fixed to the bottom of the viewport at every
width, so the old downward-opening dropdown ran off the bottom of the screen for anything past
a one-row list; this is a real, previously-live layout defect, not a mobile-only fix.
`SpaceScene.tsx`'s inline `.filter().slice(0,6)` (no stations, no ranking, no id match) is
retired in favour of the new module. One scope cut, made and then reverted after finding it
conflicted with an established contract: an "IN TRANSIT" console label for any active warp was
drafted, then removed after `mid-warp-input.spec.ts`'s TR-096 contract ("the console must show
its resting label throughout" an abort) proved the literal delivery-plan wording ("mid-warp
feedback") already means the QUEUE state specifically, which was already shipped — not a
generic in-transit indicator.

**D5.3 — Class entries.** New engine method `nearestFieldOfType(typeByte)`
(`babylon-engine.ts`, optional on `SpaceEngineElement` — Babylon-only, mirroring the
`beginAscent?`/`queuedTargetId?` convention for archived-engine-absent methods) finds the
field-catalog member of a given deep-layer population (`FIELD_TYPES`: OC/WD/SDSS/GD-1/EXO/
AST/OORT) nearest the ship, memoized per coarse camera-position epoch so it doesn't rescan
~200k field records every keystroke. The actual scan is a new pure function, `nearestOfType`
in `star-catalog.ts` (not left inline in the class), for the same off-GPU-testability reason
TR-097 extracted `raySphereDist`. Search rows read `A WHITE DWARF · NEAREST INSTANCE` style
(`FIELD_TYPES[type].sp`, uppercased, with an article), travel via D4.2's existing `fs-N`
branch. `SpaceScene.tsx` folds class rows into the live query result only while a query is
non-empty (skips the ~7 engine calls + array rebuild entirely on idle re-renders).

**D5.4 — Missing-body audit.** New `src/data/celestial/celestial-missing-moons.js`: real
curated entries for all 5 audited-absent bodies (Mimas, Iapetus, Phobos, Triton, Charon —
Deimos was never named in the audit list and stays out of scope). None has a source surface
image, so all ship `img: null` (the same honestly-non-photographic state dozens of existing
entries already carry) with real astrometric/physical data and dossier text, drafted from
standard public sources (NASA Solar System Exploration, JPL Satellite Physical
Parameters/Orbital Elements) per the D4.4 precedent — owner-approved generated drafts grounded
in official sources. Two real cross-source numeric discrepancies found and resolved rather than
silently picked: Mimas's albedo (NASA's prose page rounds to 0.5; the JPL/Wikipedia scientific
geometric-albedo figure is 0.962 — used) and Charon's density (JPL's older table gives 1.853
g/cm³; the New Horizons-refined ~1.70 g/cm³ is used). Positions are the same declared-license
visual spread `celestial-saturn-moons.js` established (real angular separation is sub-pixel at
this scene's scale): Mimas and Iapetus preserve real orbital-radius rank against the already-
shipped Saturn moons (Mimas 0.487° < Enceladus 0.685°; Iapetus 1.292° > Titan 0.926°, since
Iapetus's real radius is ~3x Titan's); Phobos/Triton/Charon are each their planet's only
catalogued moon, so offsets are modest and non-colliding only. Phobos stays under the standing
`NEVER_SPHERE` rule. New guard test (`destination-search-surface.test.ts`, D5-AC3) asserts the
travel surface — every real catalog body plus every nav station — is a subset of the search
index, forever.
