**Date:** 2026-07-18
**Scope:** [PF-09 B1](../delivery-plan/PF-09-babylon-havok-realism.md) continued — give the
WebGPU path native WGSL shaders so the owner's gate measurement reads a true WebGPU number
instead of silently falling back to WebGL2.
**Verdict: OVERALL: READY TO PROCEED** (gate decision itself still owner-pending, per
[TR-028](TR-028.md)).

## The finding that reshaped this phase

The task looked like "translate two GLSL shaders to WGSL". It is not. **WebGPU has no
`gl_PointSize` equivalent**: WGSL dropped the `point_size` builtin and `point-list` renders
1×1-pixel points, because native APIs disagree on point semantics. Babylon states the same for
its own backend — _"StandardMaterial in WebGL2 recognizes pointSize, but WebGPU does not, and
all points are the default size."_

The live engine draws its 168k stars as **variable-size point sprites** (`gl_PointSize` +
`gl_PointCoord`). **That technique cannot run on WebGPU at all.** Porting the renderer therefore
requires re-architecting the star field into camera-facing **billboard quads** — a change of
rendering technique, not a shader translation. Surfacing this is exactly what the B1 spike is
for, and it materially raises the cost estimate for the full catalog port (B2).

## What changed

1. **Star field → billboard quads** ([star-field.ts](../../src/lib/star-field.ts)
   `buildStarBillboards`, pure + tested): 4 verts + 6 indices per star, each vertex carrying the
   star centre and `corner = (cx, cy, size, colourT)`; the vertex shader billboards in view
   space. One technique on **both** backends, so the CI-testable WebGL2 path exercises exactly
   the geometry WebGPU needs.
2. **WGSL twin** — `ShaderStore.ShadersStoreWGSL` now carries Babylon-flavoured WGSL vertex +
   fragment shaders alongside the GLSL pair; `ShaderMaterial` selects
   `ShaderLanguage.WGSL` when the backend is WebGPU, `GLSL` otherwise.
3. **`sceneStats()` diagnostic** on `<babylon-scene>` (backend, star count, active meshes/indices,
   material readiness) — used by CI's geometry assertion and useful on the owner's devices.
4. **Pixel-proof E2E** — asserts real lit pixels on the canvas, not just `cosmos:ready`.

## Rejected along the way (recorded so B2 doesn't repeat them)

| Approach                       | Why rejected                                                                                                                                                                                                   |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Point sprites (`gl_PointSize`) | Unavailable on WebGPU — the core reason this phase exists.                                                                                                                                                     |
| Babylon **thin instances**     | Require a per-instance `matrix` buffer; with only custom buffers, `thinInstanceCount` stays **0** and nothing draws (measured via `sceneStats()`). Carrying ~10.8 MB of matrices was not worth it for a spike. |
| Barrel `@babylonjs/core`       | 1.1 MB gz (TR-027) — replaced by subpath imports in TR-028.                                                                                                                                                    |

**Tree-shaking gotcha worth remembering:** subpath imports drop prototype augmentation. Thin
instances additionally need `import "@babylonjs/core/Meshes/thinInstanceMesh"` or
`thinInstanceSetBuffer` is `undefined` at runtime. The same class of bug will bite any Babylon
feature added in B2+ (loaders, post-processes) — always import the side-effect module.

## Verification

| Step         | Result                                                                                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit         | **86/86** (+2: billboard geometry — centre repeated per corner, corners ∈ {−1,1}, size/colour carried, indices confined to each star's own verts; 32-bit index range at catalog scale) |
| E2E          | **52/52** (+1 pixel proof)                                                                                                                                                             |
| Build · lint | Exit 0 · 0 (prettier clean; WGSL + `ShaderLanguage` compile)                                                                                                                           |
| Bundle       | Babylon **330 KB gz** (unchanged by the technique switch); default path **260 KB gz** unchanged                                                                                        |
| In-browser   | Full catalog drawing: `activeIndices` **1,013,754** (= 168,959 × 6), `totalVertices` **675,836**, **237,959 lit pixels** (~26% of a 1280×720 viewport), no page errors                 |

The pixel assertion earned its place immediately: the first billboard attempt (thin instances)
booted, reported `cosmos:ready`, and drew **nothing** — `cosmos:ready` alone would have passed it.

## Honest limitations

- **The WGSL path is written but UNVALIDATED.** CI has no WebGPU adapter (`Could not retrieve a
WebGPU adapter`), so every automated run exercises WebGL2. The owner's device run is the WGSL
  twin's first real execution — if it errors there, that is a finding, not a surprise.
- **Memory cost:** billboards use ~23 MB of vertex/index data vs ~2.7 MB for the live engine's
  point sprites (~8×). Acceptable for a spike; B2 should reduce it via matrix-backed thin
  instances or a compute-driven path before shipping.
- Star field is still procedural; the streaming catalog + photometric/relativistic port remains B2.
