## Part 1 — C0 hardening

### 1a/1b. Regression tests for the two format readers (real gap closed)

`scripts/lib/votable-binary2.mjs` and `scripts/lib/fits-bintable.mjs` were proven live against
real data in TR-061/TR-063 but had **zero committed regression coverage** — a future edit to a
byte offset could silently break either with no CI signal. Closed with
`tests/unit/votable-binary2.test.ts` (6 tests) and `tests/unit/fits-bintable.test.ts` (6 tests),
12 new tests total. Both use independently-constructed fixtures (a small local encoder, not a
reuse of the reader's own logic) written to real temp files — not the gitignored `resources/`
datasets, so the suite stays CI-safe. The FITS test fixture deliberately reproduces the real
white-dwarf file's VOTMETA-primary-HDU-data shape (the exact structure TR-063 discovered), so a
future regression in that specific parsing path — not just the common case — would be caught.

### 1c. Real bugfix: Hunt-Reffert compound-name matching (`gaia-dataset-pipeline.mjs`)

Flagged as a known gap in TR-063, fixed and verified against the **full real 7,167-row
Hunt-Reffert 2023 file**, not a synthetic case. Two real, previously-undiscovered bugs surfaced
running the fix against the complete file (not just the small hand-picked sample used during
earlier development):

1. **Compound cross-match names weren't searchable.** Hunt-Reffert stores a cross-matched
   cluster's `name` as a pipe-delimited list of every catalog's designation for the same object
   (e.g. the Hyades is `"Collinder_50|Hyades|MWSC_379|Melotte_25|OCL_456|Taurus_Moving_Cluster"`).
   `--names "Hyades"` failed outright against this data. Fixed: `buildNameIndex` now indexes
   every individual designation within a compound name, and `chooseDisplayName` picks the
   searched-for designation for display (`n`/`id`) rather than the whole compound string.
2. **A real crash on `row.name === null`.** Some Hunt-Reffert rows have a genuine BINARY2
   null-bitmask hit on `name` — undiscovered because the earlier small sample never happened to
   include one. `splitDesignations` now returns `[]` for a null name instead of throwing.
3. **787 real designation collisions** surfaced on the full file — Hunt-Reffert 2023 has
   thousands of rows sharing a cross-match ID with a genuinely different row (overlapping
   candidate detections in the source survey, not a defect in this reader). Originally logged
   one warning per collision (dozens of lines of noise on a real run); now counted and
   summarized in one line. First claim wins, which is itself a known, documented limitation —
   see "Known limitations" below.

Verified live: `node scripts/gaia-dataset-pipeline.mjs --dataset hunt-reffert-2023 --names
"Hyades,Melotte_22"` now resolves both correctly against the full real file (no crash, no
per-collision spam, correct display names).

### 1d. Astra REALISM-AUDIT — Track B colour/type-byte calibration

Full findings: consumed inline this session (no separate science-brief file — compact enough
per Astra's own assessment). Two verdicts:

- **Colour byte (`bp_rp` → `[-0.5, 2.0]`): SIMPLIFIED.** Right physics (BP-RP is a genuine
  temperature/colour proxy for white dwarfs too), wrong range — a main-sequence-shaped span
  wastes most of the byte's dynamic range on a population that's much bluer and narrower.
  **Recommendation, not yet applied:** tighten to `[-0.6, 1.2]`, the real literature-informed
  white-dwarf colour span. Also flagged: since the magnitude byte already saturates for this
  entire population (TR-063), colour is the _only_ surviving differentiator — this raises the
  importance of getting the range right, not lowers it.
- **Object-type byte (`= 1`, provisional): recommend `0` instead** (shared with ordinary
  stars) — a genuine reversal of the original assumption. White dwarfs are point sources, not
  extended deep-sky objects; forcing them into a "deep-layer class" bucket implies a rendering
  treatment (extended shape) that would misrepresent what they actually look like. Caveated:
  Astra doesn't have visibility into what the shader's type-byte branches on today — Procyon
  must verify against `babylon-engine.ts` before applying, not apply blindly.

**Neither recommendation has been applied to code yet** — `gaia-whitedwarf-pngpack.mjs` still
ships the original `[-0.5, 2.0]` range and `type=1`. This is C1 rendering-integration work
(white dwarfs aren't wired into any rendering path yet at all), recorded here so it isn't lost.

## Part 2 — C1 IMPLEMENT: star clusters wired live

### What changed

- **`src/data/celestial/celestial-clusters.js`** (new) — the 35 reviewed cluster entries from
  [`docs/datasets/star_clusters_hall_of_fame.md`](../datasets/star_clusters_hall_of_fame.md),
  generated programmatically from that file's two JSON blocks (not hand-retyped, to avoid
  transcription error) with one real fix applied: `mg` was numeric in the review doc but
  `CelestialEntry.mg` is typed `string` (a display string, matching `celestial-gaia.js`'s own
  `"—"` convention) — stringified during generation, verified by type (`typeof sample.mg ===
"string"`) before shipping.
- **`SpaceScene.tsx`** — added to the existing `Promise.all` catalog-loading chain, same pattern
  as the other four `celestial-*.js` files.
- **Zero rendering code changed.** Real finding confirmed by reading `celestial-bodies.ts`
  before writing any code: `"cluster"` is **already** a fully-handled type in the existing
  billboard pipeline (`PROCEDURAL_TYPE`/`PHOTO_TYPE` tables, `proceduralTypeCode()` splitting
  globular (4) from open (5) via a `/globular/i` test against the entry's `sp` field — exactly
  matching this data's `"Globular cluster"`/`"Open cluster"` values). This was genuinely a
  pure data-wiring task, as the PF-10 plan predicted for NGC2000 nebulae and expected here too.

### Proof

2560` (2,525 pre-existing + 35 new, zero id collisions), `window.CELESTIAL_CLUSTERS_COUNT ===

- **New E2E test** (`tests/e2e/engine-select.spec.ts`, "PF-10 star clusters ... load and are real
  travel targets"): asserts the real counts above, asserts Pleiades' real `ra`/`dec`/`ly` values

  and polls for `arrivedId === "cluster-pleiades"` — proving the cluster is a genuine reachable
  destination through the real `travelTo` state machine, not just an entry sitting in an array.
  Passes in isolation and as part of the full suite.
