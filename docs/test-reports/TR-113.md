## C1 (CRITICAL) — D7.1 froze the renderer on every load

### Symptom

`renderFrames` climbs 0 → ~10 and then never advances again. Not a hang: an uncaught
exception thrown inside `scene.render()` on every subsequent frame.

```
TypeError: Cannot read properties of undefined (reading 'boundingSphere')
    at RenderingGroup._RenderSorted → _renderTransparentSorted → RenderingGroup.render
    at RenderingManager.render → Scene._renderForCamera → Scene.render
    at babylon-engine.…  ← the runRenderLoop callback
```

The throw lands **before** `this.renderFrames++`, so once it starts it can never stop. Nothing
downstream of a drawn frame completes again: the D1.3 launch ascent never finishes so
`body.ij-loading` is never cleared; `travelTo` never arrives so `arrivedId` stays `null`;
Havok bodies never integrate; the band's chunked build stalls. That is the entire failure
list — the `Expected: "sirius" / Received: null` family (~25 specs), `renderFrames did not
advance (before=3, after=3)`, `Havok velocity 0`, `constellation segments 0`, and the
`console-clean` assertions, which were correctly refusing to tolerate the exception itself.

**This was a production defect, not a test defect.** Reproduced on the owner's own machine on
the WebGPU path, not only on SwiftShader.

### Root cause

`_applyStarFieldGeometry()` (`src/lib/babylon-engine.ts`) is the ONE of D7.1's three
`clearCachedData()` sites that runs **twice** — at boot, then again when
`_loadBonusStarLayers()` merges ~387k bonus records into the base star mesh (168,959 →
555,825). Babylon derives the mesh's `BoundingInfo` from the CPU-side POSITION cache; with the
cache dropped, the rebuild leaves `getBoundingInfo()` undefined, and the transparent depth
sort — which reads `.boundingSphere.centerWorld` to order alpha-blended meshes — dereferences
it.

D7.1's own comment asserted the exact property that is false:

> `setVerticesData`/`setVerticesBuffer` … always build a fresh Geometry rather than reuse the
> cleared one, **so clearing here cannot break the next bonus-layer rebuild.**

A fresh `Geometry` is indeed built. The bounding info is not reconstructible from it. That
claim is **withdrawn** in the source and in TR-111.

### How it was isolated (CLAUDE.md #27 — never run the full suite to characterise one failure)

| Experiment                                                              | `renderFrames` over 26 s | Advancing?                |
| ----------------------------------------------------------------------- | ------------------------ | ------------------------- |
| As committed (`da57ae9`)                                                | 0 → 10 → 10 → 10         | no                        |
| `?layers=sdss-field:0,belt-visual:0`                                    | 10 → 10                  | no                        |
| `?layers=sdss-field:0`                                                  | 10 → 10                  | no                        |
| `?layers=belt-visual:0`                                                 | 10 → 10                  | no                        |
| `refreshBoundingInfo()` + `_createGlobalSubMesh(true)` before the clear | 10 → 10                  | **no**                    |
| `clearCachedData()` removed from `_applyStarFieldGeometry`              | 0 → 23 → 33 → **49**     | **yes**, zero page errors |

Rows 2–4 clear the SDSS and belt meshes (their clears are harmless — built once, never
rebuilt). Row 5 is recorded because it is a **negative result that changed the fix**:
reconstructing the bounding info immediately before clearing does _not_ work, because Babylon
re-derives and re-nulls it from the absent cache afterwards. Row 6 is the shipped fix.

### Fix

`clearCachedData()` removed from `_applyStarFieldGeometry` only. **D7.1's win is mostly
retained**: the two genuinely one-shot meshes keep their clears —
`_loadSdssGalaxyLayer` (~361 MB, the large one) and `_loadAsteroidVisualLayer` (~15 MB). Only
the rebuildable star mesh (~54 MB) keeps its CPU copy.

**Rule this establishes, recorded in the source at the fix site:** never `clearCachedData()`
on a mesh whose geometry will be rebuilt.

## H1 (HIGH) — the crashing path was the one with no off-switch

`_loadBonusStarLayers()` was deliberately un-gated, because `bonus-stars` was
`implemented: false`. So the heaviest post-first-frame work the engine does (~5.8 MB across
four chunks, +387k billboards, plus the full star-mesh rebuild) — and, once C1 landed, the
thing that killed the scene — could not be disabled by any URL, toggle or tier. The scene was
unrecoverable and the defect was harder to isolate than it needed to be.

The merge is now gated on the resolved layer state: **`?layers=bonus-stars:0` is a real escape
hatch.** It cannot be un-merged live (one draw call, by design), so the layer is
`status: "reload"` — see H4 — and the panel labels it `APPLIES ON RELOAD` rather than
pretending it is live.

## H2 (HIGH) — the gate was reported as passed while unrun

Recorded rather than fixed, because it is a process finding: TR-111/TR-112 issued
`READY TO PROCEED` with E2E unrun, and the delivery plan marked D7/D9 delivered on that basis.
Both TRs now carry a superseding note; the plan rows now point here.

The generalisable part: **880 green unit tests certified a build whose renderer was dead.** No
jsdom test instantiates WebGPU or WebGL, so this entire defect class is structurally invisible
to `npm run test`. Unit-green is not evidence about rendering. The regression guard that was
missing is now in `engine-select.spec.ts` — see Test changes.

## H3 (HIGH) — `RESET TO AUTO` did not reset to auto

`RenderConsole.tsx` removed `ij-layers` from `localStorage`, then called `applyPreset()` →
`setLayers()`, which **unconditionally re-persisted the full state**. The key was deleted and
immediately rewritten. The live session looked right — which is why a manual check would never
have caught it — but on the next load the visitor was pinned to an explicit stored override of
whatever tier they happened to be on, permanently off the device tier. That is the precise
opposite of the control's label and it defeats ADR-0010's "tiers are the default, never the
ceiling" for anyone who clicks it.

`setLayers(config, { persist })` added; `RESET TO AUTO` is its only `persist: false` caller.

## H4 (HIGH, structural) — `implemented: boolean` could not describe reality

One boolean was carrying three different meanings — "always on by design" (`star-field`),
"controllable, but only at boot" (`bonus-stars`), and "does not exist yet" (`gaia-tiny`) — so
the panel had to guess, and guessed wrong (M1). Replaced with an explicit four-way
`status: "live" | "always-on" | "reload" | "unavailable"`, plus `isLiveToggleable()` /
`isAvailable()`. Each value has exactly one rendering in the panel and one meaning to
`setLayers()`.

**This is the D8 unblock.** Shipping Gaia DR3 Tiny is now a one-value change in
`render-layers.ts` (`"unavailable"` → `"live"`) plus its data pipeline — no panel change, no
new mechanism.

## Medium

**M1 — `gaia-tiny` rendered as CHECKED.** Every non-live row was hardcoded `checked disabled`.
Correct for `star-field`; for `gaia-tiny` the panel was asserting that 2.55M stars were being
drawn from a dataset that does not exist. Now status-driven: `unavailable` renders off,
`always-on` renders on. Its E2E test was titled _"always-off row"_ but only asserted
`toBeDisabled()` — the missing `not.toBeChecked()` is added in both the E2E and unit specs.

**M2 — `render-console.spec.ts` strict-mode violation.** `getByText('DATA & LICENSES ▸')`
matched two nodes (the mobile menu's `[data-mobile-menu-action="credits"]` item and the HUD
button). This failed **independently of C1**, on a healthy build. Scoped to the HUD button.

**M3 — unbounded `belt-physics` count.** `min={0}`, no ceiling, and the value becomes a Havok
rigid-body budget stepped every frame. `maxCount: 192` added to the registry (4× the `full`
budget — explicitly a headroom ceiling, **not** a measured safe maximum; D9.4/D0.3 owns the
real number), and `clampLayerValue()` is applied at **every** entry point: URL param, stored
JSON, the panel input, and `setLayers()` itself.

**M4 — the documented boot-time `layers` attribute did nothing.** `attributeChangedCallback`
fires before `connectedCallback` for attributes already in the markup, so its `setLayers()`
was overwritten wholesale by `connectedCallback`'s `resolveLayers()` one tick later. The
attribute is now folded into the resolution order between the tier default and the URL param.

**L1 (low, taken since it was one line) — `serializeLayersParam` documented a caller that did
not exist.** Rather than delete the claim, the caller now exists: a `COPY LINK` button that
puts a `?layers=…` share URL on the clipboard. It was already the obvious affordance for a
panel like this and the serializer was already written and tested.

## Test changes

**Additive (the guards whose absence let this ship):**

- `engine-select.spec.ts` — **"the star mesh survives the bonus-layer rebuild"**: asserts
  `starCount` grows past the base catalog (proving the rebuild ran, so it can never pass by
  never merging) AND that `renderFrames` still advances afterwards, AND zero `pageerror`.
  This is the exact assertion class C1 needed and no spec had.

- `render-console.test.tsx` — `RESET TO AUTO` leaves storage empty and calls
  `persist: false`; `gaia-tiny` unchecked; `star-field` checked; `max` attribute and clamped

### The E2E run found three more defects the review did not — all in never-run specs

Worth recording precisely, because it sharpens H2 rather than merely restating it. The first
full run came back **171 passed / 1 failed**, and fixing that one exposed another. None was a
product defect; all three fail against a perfectly healthy build:

1. **`render-console.spec.ts` read `arrivedId` from `sceneStats()`.** It is a property on the
   ELEMENT — the spec's own `EngineHandle` type declares it as a sibling of `sceneStats`, and
   every other spec in the suite reads it off the element. It polled `undefined` for the full
   40 s and **could never have passed**, in any build, ever.
2. **The console's focus test never dismissed the D1.2 PRE-FLIGHT gate.** PreFlight moves
   focus to LAUNCH the moment it arms, racing the dialog's `toBeFocused()`. This one
   **passed in the full-suite run and failed in isolation** — the direction people
   instinctively distrust, and a reminder that "green in the suite" is not the same as
   deterministic. TR-107 fixed this exact class once before; `render-console.spec.ts` was the
   only Babylon spec in the repo not following the SKIP INTRO convention. Now applied
   uniformly via a `boot()` helper to all ten tests, not patched into the one that failed.
3. **M2's strict-mode locator**, already described above.

**The cost of deferring E2E was therefore not one masked defect — it was four**, of which one
was fatal in production and three would have failed on day one. A written-but-unrun spec is
not coverage; it is an untested assertion about an untested system.

`render-console.spec.ts` re-verified 10/10 in isolation after the fixes, then 172/172 in the
full suite.

## What this proves, and what it does not

**Proven by automated coverage:** the renderer survives the bonus-layer rebuild and keeps
drawing; travel, ascent, arrival, physics and the frame ladder all work again; the layer
toggles do what the panel says; the clamp holds at every entry point; `RESET TO AUTO` leaves
nothing behind.

**NOT proven here, unchanged from TR-111/TR-112:**

- **Real-device heap/VRAM measurement has still not run.** D7.1's memory numbers
  (~361/15/54 MB) remain _estimates from record counts and strides_, not measured. The star
  mesh's ~54 MB is now retained rather than freed — that is a real, unmeasured regression
  against D7's own goal, and it is the price of a renderer that runs. D0.3 owns the number.
- **D9.4's defaults are still not D0.3-calibrated** — they mirror current shipped behaviour.
  `maxCount: 192` joins them as a deliberate, uncalibrated headroom figure.
- **Owner-eyes visual confirmation.** The suite proves frames advance and meshes exist; it
  does not prove the merged star field _looks_ right. Recommended manual pass on
  `npm run preview`: boot console-clean → travel near (Moon/Mars) → far (M42) → arrival
  dossier → Where-To search → classic view → reduced motion → open RENDER ▸, toggle SDSS and
  the belt, click RESET TO AUTO, reload and confirm the device preset is back.
