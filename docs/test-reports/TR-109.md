## What shipped

**D6.2 — Belt frame re-expression to the obliquity-inclined basis (GO, ADR-0010).** The
asteroid belt model (`babylon-asteroids.ts`: spine circle, herding pull, gaussian density,
orbital rotation) was tuned entirely in an unrotated frame where the ring's X-Y plane was
treated as world Z-pole — astronomically wrong, since the real Gaia DR3 belt is heliocentric
ECLIPTIC and the rest of this scene's catalog is EQUATORIAL, putting the belt 23.44° off the
real zodiac. New `toBeltSpace`/`fromBeltSpace` rotation helpers (`OBLIQUITY_J2000_DEG =
23.439281`, mirroring `scripts/lib/asteroid-kepler.mjs`'s `eclipticToEquatorial` exactly) let
every belt-model function convert a world-space point into the tuned local frame, run the
UNCHANGED math, and convert back. **A real correction landed mid-implementation, not silently
absorbed:** the first draft's basis change didn't account for `ASTEROID_BELT.center` being a
world-frame translation applied AFTER rotation (mirroring `eclipticToWorld`'s own rotate-then-
translate order) — fixed to translate-then-rotate for points in, rotate-then-translate for
points out, rotation-only for vectors (accelerations, velocities). `heliocentricRadius` needed
**zero** code change, which is also the strongest proof the final design is correct (distance
to a fixed point is rotation-invariant regardless of how the surrounding axes are oriented).
Both shader twins (GLSL + WGSL) got the identical basis-change block in the orbital-motion
vertex code. Real Gaia DR3 data regenerated: `node scripts/gaia-asteroids-pngpack.mjs --date
2026-07-20 --physics-count 64 --frame equatorial` (154,662 objects streamed, Kirkwood gaps
still present in the console report — frame-invariant, confirming the rotation is pure).
`distanceToBeltSpine` (asteroid-kepler.mjs) gained the same `frame` parameter `eclipticToWorld`
already had, since the physics-subset SELECTION ranks candidates by spine distance and that
ranking has to match whichever frame the candidate positions actually landed in.

**The m42 showcase route is retired, not patched.** Measured directly: m42's peak belt density
collapsed from ~0.98 (old, unrotated) to ~0.0001 (new, correct) — Orion is not a zodiacal
constellation, so a correctly-oriented belt has no reason to intersect it. Retuning
`ASTEROID_BELT.center` to force the old crossing back was rejected (computed: it would require
moving the belt's centre ~80 world units, a drastic change to the belt's overall scene
placement for one showcase route, and the same fitted-coincidence error class this slice
exists to remove). Instead, several already-catalogued destinations were tested numerically
against the corrected belt; **Aldebaran** (α Tauri, ra 68.980°/dec 16.509°) threads it at peak
density ~0.96 — Taurus is a real zodiacal constellation, so this is real astronomy working as
predicted. `tests/e2e/engine-select.spec.ts`'s belt-slowdown assertion now flies home first
(the ship is parked at m42 from that test's own nebula-reveal block), then to Aldebaran, before
asserting `warpSlowMin` — a named test change (CLAUDE.md #15).

**D6.6a — Atlas cells for Tethys/Dione/Rhea.** New `scripts/patch-atlas.mjs` (three-mode,
never deletes): `isPhotoEligible` (`celestial-bodies.ts`) requires both `img` and an atlas-map
entry, and these three shipped `img` since TR-079 but no atlas cell, so their flat
photographic billboard (used at range, before the sphere upgrade) silently fell back to a
plain point. The packed 16×16 atlas macro-grid had exactly one genuinely free cell (row 3,
col 2 — confirmed blank by measurement: a real ~800 B re-encoded region vs ~148 KB for a real
photographic cell at the same crop size), subdivided 2×2 for the 3 new cells (1 spare).
Sources: `public/assets/planets/{tethys,dione,rhea}.jpg` (1024×512 equirectangular, already
committed), centre-cropped to 512×512 and resized to 128×128. `photoBodyCount` (HUD "N PHOTO")
rose 267 → 270, confirmed live. `budgets.config.mjs` raised deliberately (compositing forces a
full atlas re-encode — `mozjpeg: true` at quality 90 chosen as the conservative middle point
between an oversized default encode and undercutting the original file's own size).

**D6.6b — Jupiter moon rank-honest offsets.** Io and Europa's declared visual-spread offsets
from Jupiter were swapped relative to their real orbital radii (421,700 km vs 671,034 km) —
fixed by swapping their catalog ra/dec (a minimal data-only change), matching the exact
rank-honesty convention `celestial-saturn-moons.js` already established for Saturn. New
standing guard test (`moon-offset-rank.test.ts`) covers both systems going forward.

**D6.7 — PF-10 plan header correction.** Additive correction (strikethrough in place, dated
forward pointer, per this repo's corrections-are-additive convention) in
[PF-10's own delivery-plan header](../delivery-plan/PF-10-gaia-dataset-realism.md): the stale
"221 MB" asset-weight figure corrected to the real measured 256.01/256.34 MB. The same edit
also resolved the adjacent belt-frame-decision reference now that D6.2 is GO-and-delivered.
