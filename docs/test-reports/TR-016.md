# TR-016 — Page-Load Console Hygiene: CSP Inline Styles, 0-Byte Fonts, frame-ancestors

**Date:** 2026-07-17
**Scope:** Pre-existing page-load console errors invisible to the E2E suite (its listeners attach post-`goto`)
**Verdict: OVERALL: READY TO PROCEED**

## Findings and Fixes

### 1. CSP-blocked inline styles — `AstronautMascot.tsx` (visual defect in production)

The component SSR'd **both** blocked forms: a `style="top:200px;transition:…"` attribute
(style attributes are never covered by CSP hashes) and an inline `<style>` element with the
float keyframes (Astro only hashes its own bundled styles, not React island SSR output). Since
the TR-010 CSP landed, **the mascot's float animation and positioning have been dead in
production**. The space islands' `style={{…}}` props are unaffected — they render client-side,
where React writes style _properties_ (CSP-exempt).

**Fix:** static position/transition/reduced-motion moved to `global.css`
(`.astronaut-mascot`, `.astronaut-float` — reusing the already-present `ij-float` keyframes,
of which the component's inline copy was a duplicate); dynamic `top` written post-hydration via
`el.style.top`. The `prefersReducedMotion` React state fell away entirely — CSS
`@media (prefers-reduced-motion: reduce)` covers it. Verified live: no `style` attribute, no
inline `<style>`, `top: 200px`, `transition: top 2s`, `animation: ij-float 8s` all computed.

### 2. Both web fonts were 0-byte files — broken since the first commit

`public/fonts/inter-var.woff2` and `space-grotesk-var.woff2` were committed **empty at
"Project setup"** and have never decoded anywhere — the site has always silently rendered
fallback system fonts (`font-display: swap` hid it). Same defect class as the TR-007 0-byte
`HUDF.webp`.

**Fix:** real variable fonts installed from `@fontsource-variable/inter` /
`@fontsource-variable/space-grotesk` (pinned devDependencies), latin `wght` subsets copied to
the existing paths (48,256 B / 22,288 B, valid `wOF2` signatures) — `@font-face` declarations
and preloads unchanged. OFL license texts shipped alongside (`LICENSE-inter.txt`,
`LICENSE-space-grotesk.txt`). E2E now asserts `document.fonts.check()` for both families.

### 3. `frame-ancestors` in the `<meta>` CSP — dead directive, live console error

Browsers ignore `frame-ancestors` delivered via `<meta>` and log an error for it. Verified
`public/_headers` ships `X-Frame-Options: DENY` (the effective anti-framing control, already
documented in the config comments). **Fix:** directive removed from `astro.config.mjs` with an
explanatory comment — zero change in effective security posture, one less guaranteed console
error.

## New Regression Guard

`tests/e2e/page-load-console.spec.ts` — the one spec that listens **from navigation start**
(the rest of the suite deliberately scopes post-load): asserts zero console/page errors through
initial load, and that both fonts genuinely load and apply.

## Notes
