# TR-058 — GAP-06 through GAP-16 closed: aberration, free-look, hover, events, attributes

**Date:** 2026-07-20
**Scope:** Implement [GAP-06 through GAP-16](../analysis/2026-07-19-webgl-babylon-cutover-gap-analysis.md)
— relativistic aberration/Doppler, ember sparks + idle hull bob, free-look drag, field-star +
body hover picking, keyboard accessibility, station sprite markers, HTML attribute parity, a
scoped scroll-cadence port, and three silently-degrading event-contract gaps (`cosmos:aim`,
`cosmos:craft`, `cosmos:hover`/`cosmos:unhover`). Continuation of TR-056/TR-057's GAP-01…05
pass, same implementation guardrail (`space-engine.js` frozen; every port is a new Babylon-side
pure module or shader twin, not a shared import).
**Verdict: OVERALL: READY TO PROCEED** — **299/299 unit · 71/73 E2E** (same 2
environmental-only `webgpu-hardware.spec.ts` exclusions as TR-056/057, see Verification), lint

## What shipped, by gap

**GAP-14 — `cosmos:aim`.** The HUD's RA/Dec readout was rendering its permanently-wrong initial
literal. Now emitted every 8th frame (matching the live engine's own throttle) from the camera's
_actual_ current forward direction (`quatRotate(camQuat, BABYLON_FORWARD)` inverted through the
same ra/dec formula `bodyWorldPosition` uses to place catalog entries) — correct regardless of
whether idle drift, free-look, or warp chase-look is driving orientation that frame, since it
reads the result rather than tracking a second source of truth.

**GAP-15 — `cosmos:craft`.** `_setupShip`'s three state transitions (loading/ready/error) now
pair `dataset.craftState` with a matching `cosmos:craft` emit, exactly mirroring
space-engine.js's `_loadCraft`. Un-pins the landing gate: `state.ready && state.craftDone` is
asset-driven again instead of fixed on the 2.5s grace-timer fallback on every load.

**GAP-08/GAP-10 — free-look (drag + keyboard) and canvas keyboard access.** A new yaw/pitch
free-look layer (`freeLookDir`, unit-tested) parametrizes look direction as a standard
yaw-then-pitch turn away from `BABYLON_FORWARD` — deliberately **not** a literal port of the live
engine's yaw/pitch-as-ra/dec convention, which would gimbal-lock at this camera's identity
forward (see the function's header for the derivation). Pointer drag sets yaw/pitch directly
(same sensitivity constant, same ±83° pitch clamp as the live engine); `_dragging` stays
authoritative over chase-look mid-warp, exactly as ADR-0006 named the gap. Arrow keys nudge a
damped angular velocity; Enter travels to whichever body/station projects nearest screen centre;
H returns home. `tabIndex=0`/`role="application"`/the live engine's own `aria-label` text move
onto `<babylon-scene>` itself (the canvas stays out of the tab order — see the GAP-11 note on
why bodies aren't).

**GAP-11 — station sprite markers.** Ported `_projectBodies`' 76px edge-clamp using this file's
own quaternion-basis convention (`quatRotate` + `camera.fov`/aspect) rather than introducing
Babylon's `Matrix` API as a second, differently-conventioned way to do the same job. Only the 7
stations are projected every render-loop frame (the only DOM consumer, `SpaceScene.tsx`'s sprite
`tick()`); curated bodies are projected on-demand at pick time instead of unconditionally every
frame — see GAP-09.

**GAP-09/GAP-16 — field-star + body hover picking.** `fieldInfo(i)`, `_pickField` (~0.6° cone,
throttled to every other pick attempt — an O(starCount) test), `_pick` (34px body radius, then
the field-star fallback), and `_click` all ported. `cosmos:hover`/`cosmos:unhover` now actually
fire; `HoverTooltip` stops being dead code on the default path. Deliberate architecture note:
curated bodies are projected **at pick time**, not every frame (unlike the live engine) — they
already render as real GPU billboards (GAP-01/02), so nothing DOM-side needed their screen
position continuously; this keeps the render loop's per-frame allocation at zero while still
covering every pickable target.

**GAP-06 — relativistic aberration + Doppler.** The real centerpiece of this pass. Ported into
five shader pairs (GLSL+WGSL twins each): the star field and curated-body beacons get the full
treatment (position aberration + blueshift/beaming ahead, redshift/dimming astern — bodies go
through the same beacon pipeline the live engine's STAR_VS `uMode>0.5` branch does); photo
billboards and warp trails get position-only aberration (matching the live engine's own
PHOTO_VS/TRAIL_VS, neither of which had a Doppler colour term); the Milky Way band gets a
Doppler colour tint only (see "Descoped, named" below for why the positional half didn't port).
Constellation figures also picked up their long-deferred relativistic alpha fade
(`0.34 * (1 - beta)`), closing the "GAP-06 dependency" TR-057 left open for them. `beta`/`gamma`
are computed once per frame in `_tickWarp` from the same brachistochrone profile the HUD readout
already uses (so the visual crowding and the reported v/c never disagree), decayed at 0.86×/frame
outside an active warp, and pushed to every material via one `_pushAberration` call — zero new
per-frame allocation (one reused scratch `Vector3`/`Color4`).

**Adaptation, not literal restatement:** Babylon's `view` matrix bakes in camera translation
(unlike the live engine's rotation-only view matrix + manual `aPos - uCam` subtraction), so
every `aberrate()` twin operates on the already-view-space position with a view-space warp
direction (`mat3(view) * uWarpDir`) rather than a world-space vector — algebraically equivalent,
derived before writing the WGSL twin (same discipline TR-057's trail-shader bug fix established).

**GAP-07 — ember sparks + idle hull bob.** Burn-start/stop spark bursts (14/8 particles,
matching the live engine's F3 counts exactly), capped at 48 concurrent, spawned at a randomly
chosen engine nozzle with the same jitter/drift-back bounds, stepped via `ship-dynamics.ts`'s
already-existing `stepEmber` (unused until now). Rendered as billboard quads (WebGPU has no
`gl_PointSize`, CLAUDE.md #7) with continuous alpha/size-by-life rather than the live engine's 3
discrete draw-call buckets — that bucketing existed for legacy's per-bucket `gl.POINTS` batching,
not as a deliberate visual step, so a continuous fade is the more faithful reading of "fades
instead of popping." **Deliberately re-architected, named:** embers resolve to world space once
at spawn (using the ship's quaternion/scale at that instant) and step in true world space
thereafter, instead of the live engine's local-space-plus-current-transform trick — physically
cleaner (a moving craft's sparks are actually left behind) and avoids a second billboard-parented-
to-a-rotating-node technique. Idle hull bob is a small sinusoidal offset along the camera's local
"up," scaled to the ship's own apparent size rather than a literal NDC-unit port (the live engine
bobs a 2D sprite's screen Y; this ship is a real 3D mesh) — gated off during "warp" exactly like
the live engine's own `reduced || warping` check.

**GAP-12 — HTML attribute parity.** `observedAttributes`/`attributeChangedCallback` added for
`density` (reduces the star mesh's drawn index count — an approximation of the live engine's
exact decimation algorithm, which sits outside this gap's cited source ranges, named not hidden),
`constellations` (show/hide), `ship` (force-hidden regardless of warp/dock state), and `craft`
(a markup-level default, deliberately layered _below_ the URL param / stored-override precedence
CLAUDE.md documents and _above_ the device-auto policy — the live engine's `craft` attribute has
no such layering at all, since it has no URL/stored system to layer under).

**GAP-13 — scroll-linked behaviour (scoped).** The live engine's four screen-space flight
stations (warping / corner-escort / parked-under-dossier / hero) choreograph a 2D sprite's NDC
position — no clean analogue exists once the ship is a real 3D mesh flown by the chase camera
(the same architecture split GAP-11 already notes for station markers). What _does_ port cleanly
and is a genuine perf win: halving the render cadence once the visitor has scrolled the scene
mostly out of view (>55vh) and nothing is in flight. Camera/warp state still ticks every frame
(so travel triggered while scrolled resumes correctly); only the GPU draw itself skips every
other frame.

## A real regression caught by the existing a11y spec, not assumed fixed

Registering real canvas pointer listeners for GAP-08 gave Babylon's own lazy internal pointer
setup a reason to run, and it turns out the engine's `tabindex="1"` self-stamp (CLAUDE.md #22,
originally fixed in TR-052) isn't a one-shot event — it can re-stamp on a _later_ frame than the
single post-first-frame reassertion this file relied on. `accessibility.spec.ts`'s Babylon-path
axe check caught it (serious violation, `tabindex` > 0) on the first full E2E pass. Fixed by
reasserting `canvas.tabIndex = -1` unconditionally every render-loop frame (a trivial DOM
property write) instead of once. Re-ran the full suite after the fix — clean.

## Descoped, named

- **Milky Way band: Doppler colour tint only, no positional aberration crowding.** This pass
  samples a skybox sphere by its own built-in UV (GAP-03's Babylon-idiomatic substitution for
  the live engine's fullscreen-triangle view-ray reconstruction), not a per-pixel reconstructed
  ray — re-deriving that ray per fragment just to aberrate it, then inverting Babylon's own
  `CreateSphere` UV formula by hand, wasn't proportional for a diffuse background layer where the
  colour shift is the visually load-bearing half. The Doppler tint reuses the sphere's own
  object-space position as the observed direction (valid because the mesh is
  `infiniteDistance`-centred on the camera every frame) — no extra uniform plumbing needed.
- **`density` attribute: index-count reduction, not the live engine's exact decimation
  algorithm.** That algorithm sits outside this gap's cited source ranges; the port draws the
  first _N_ indices proportional to density rather than a statistically even resample. A rarely-
  used dev/parity knob, not exercised by the site's own markup.
- **`craft` attribute: no live reload mid-session.** The live engine supports re-triggering
  `_loadCraft()` on a live attribute change after connect; the Babylon ship track has no
  unload/reload path for the GLB+plume+ember rig at all today, and building one wasn't
  proportional to an S3 gap. The attribute is honoured as a boot-time default only.
- **GAP-13: only the render-cadence halving ported**, not the four-station 2D choreography — see
  "What shipped" above.

**E2E note — same environmental blocker as TR-056/057, same workaround.** This machine's Windows
TCP exclusion range still covers port 4321 (`netsh interface ipv4 show excludedportrange
protocol=tcp`: `4246–4345`). Worked around for this pass only: a temporary, uncommitted
Playwright config pointing at port 4410, running the **real, unmodified** spec files — deleted
after the run, not part of the shipped config. Result: **71/73 passed**, including the full
`accessibility.spec.ts` Babylon-path a11y check (after the tabindex fix above),
`flight-v3.spec.ts`'s free-look-drag-stays-authoritative test, and every `craft-ship`/
`engine-select`/`space-scene` spec touching the event-contract and ship-track surfaces this pass
changed. The only 2 failures are `webgpu-hardware.spec.ts`'s two real-hardware tests, which
hardcode `BASE_URL = "http://localhost:4321"` as an internal constant independent of Playwright's
`baseURL` fixture (that file's own header explains why — unrelated to this change, unchanged
since TR-056).

**Visual verification — a real limitation, stated plainly.** This session's Browser-pane
Chromium could not render a completed WebGPU frame at all: `scene.render()` throws
`TypeError: Required member is undefined` from `webgpuEngine`'s `getBindGroups`, during an
**instanced-mesh** draw (the Havok asteroid rocks) — confirmed, by stashing this pass's changes
and rebuilding, to be **byte-identical on the unmodified base commit** (present before any
GAP-06…16 work existed). A pre-existing, environment-specific WebGPU limitation in this
particular sandboxed browser (consistent with the class of SwiftShader/software-WebGPU flakiness
CLAUDE.md and TR-036/TR-039/TR-054 already document), not a regression from this change. No
shader-compilation errors appeared in the console for any of the new/modified shader modules
(only the same pre-existing, also-reproduced-on-base-commit `uTex`/`uTexSampler` binding warning
from an unrelated material). **The real E2E pass above is therefore the strongest evidence
available this session** — it exercises a real Playwright-managed Chromium (not this sandbox's
Browser pane) and does produce completed frames, including pixel-proof assertions for the
GAP-01/02/03/04/05 passes this session didn't touch. **Owner follow-up recommended:** a real-
device visual pass on `/?engine=babylon` — free-look drag feel, hover tooltip positioning, ember
spark burst timing, and the aberration crowding/colour-shift during a warp — the same category of
confirmation TR-056/057 already flagged as outstanding for GAP-01…05.
