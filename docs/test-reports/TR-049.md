## Design

- **Integrated warp progress.** `k` is no longer wall-clock (`t/warpDur`); it integrates
  `dk = dt/warpDur × slowFactor(beltDensity(shipPos))` per frame (`advanceWarpProgress`,
  pure). `warp.prog` is now the **single source of k** — camera, hull, HUD, and nebula reveal
  all read it (previously three call-sites derived k independently; that drift surface is gone).
- **Density/slow model (pure, `babylon-asteroids.ts`):** gaussian tube density around the belt
  spine (`beltDensityAt`), `warpSlowFactor` ∈ [0.45, 1] (`WARP_FIELD.maxSlow = 0.55`).
  Reduced motion pins the factor to 1 — TR-042's fixed-short profile is untouched.
- **Deflection:** `passageDeflectForce` — mass-scaled outward push with gaussian falloff over
  30 units, exact zero beyond 2.5 radii, finite at zero distance; applied in the same Havok
  force pass as the belt herding whenever the ship is warping.
- **Belt reorientation (deliberate, test-anchored):** the ring now lies in the **X–Y plane
  (axis Z, centre z = −13)**. `raDecToDir` maps declination onto Z, so the m42 showcase route
  (dir ≈ (0.107, 0.990, −0.094)) crosses the tube nearly dead-centre — a _guaranteed_ crossing
  the E2E asserts via engine-captured `warpSlowMin`. The first draft's Y-axis ring was crossed
  by almost no catalog route (routes' Y components are cd·sin(ra) — large for most bodies);
  caught because the E2E crossing assertion failed with `warpSlowMin = 1`.

## Defects found by verification (fixed in-run)

1. **Clamped-dt journey stretch (real device-facing bug).** First integration draft used the
   `SHIP_MAX_DT`-clamped dt; on stalling frames (loaded CI, slow devices) progress silently
   lost wall-clock time and journeys stretched several-fold — the arrival-timing E2E tests
   (distance-scaled, reduced-motion) failed immediately. Fixed: progress integrates a
   wall-clock dt capped only at 0.5 s (tab sleeps); springs keep their stability clamp.
2. **Belt orientation** (above) — the E2E designed to prove the feature proved the geometry
   wrong first.
