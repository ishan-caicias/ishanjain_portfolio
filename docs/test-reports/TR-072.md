## Part 1 — Why a licensing question came first

The plan's original assumption was that the 8 real NGC2000 "Volume" objects would be ported from
Gaia Sky's own per-object shaders (`resources/gaia_datasets/catalog-nebulae/shader/*.glsl`).
Reading all 8 found every one headed **"Licensed under CC-BY-NC-SA"** — Gaia Sky's own ports of
non-commercial shadertoy material, a real license mismatch for a professional portfolio (Gaia Sky
itself is MPL-2.0; these specific shaders are not). Flagged to the owner before writing any
shader code rather than proceeding past it; the owner chose **original shapes instead**, informed
by real astronomy via an Astra SCIENCE-BRIEF rather than guessed.

## Part 4 — The shape system (SOLID open/closed, as requested)

New `NebulaShape` type: `sphere | torus | cappedCone | box | ellipsoid | shell | union | subtract`.
Each carries a `shapeQ(shape, p)` dispatcher (JS mirror) and matching GLSL/WGSL generators
(`glslShapeExpr`/`wgslShapeExpr`) — recursive for `union`/`subtract`, so nested compositions (e.g.
Trifid's sphere-minus-union-of-3-cones) compile to one nested expression. `nebulaDensity`
generalizes from a hardcoded `q = length(rel)/radius` to `q = shapeQ(vol.shape ?? sphere, ...)` —
the `sphere` case reproduces the exact original formula (pinned by a regression test), so the 4
pre-existing showcase volumes are numerically unaffected.

**Open/closed in practice**: adding a 12th volume touches only `NEBULA_VOLUMES` (one descriptor).
Adding a 9th primitive kind touches only `shapeQ`'s dispatcher + the two shader-expression
generators (one case each) — the raymarch loop, compositing, and reveal plumbing never change.
GLSL/WGSL have no function pointers, so each volume still gets its own generated `nebMarch{i}`
function (the march loop itself is necessarily duplicated per volume — the same trade-off
ADR-0004 already made for baked constants over uniform arrays); what's shared across every volume
is the noise stack, the shape-primitive `nebQ*` helpers, and `nebDensityQ` (the shell/threshold/
noise math, now taking a precomputed `q` instead of assuming a sphere).

## Part 5 — The reveal mechanism, generalized to O(1) in volume count

The old `uReveal: vec4` swizzle hard-capped at 4 volumes (`revealComponent()` threw past index 3).
Replaced with a **2-slot active/previous scheme**: `uVolumeA`/`uRevealA` + `uVolumeB`/`uRevealB`
(4 scalars total). At most 2 volumes can plausibly have nonzero reveal at once — the current
destination, and the one just departed (still damping to 0 via the existing `fadeOutLambda`
decay) — so 2 fixed slots is both sufficient (verified: the destination-gated E2E test's
crossfade behaviour is unchanged) and genuinely O(1) for any future volume count, not just 11.
New `topTwoReveal()` (pure, unit-tested) reduces the per-volume reveal array to the 2-slot form
each frame on the CPU side; the shader-generated comparison per volume is one cheap
`i == uVolumeA` check, replacing the compile-time swizzle.

## Known limitations

- **NGC2000 C1 is now code-complete except GD-1's connected-trail visual** (an explicit open
  design decision, unchanged from TR-065/066/070).
- **Shape fidelity is deliberately simplified, per Astra's own verdicts** — Cat's Eye's real 11+
  concentric shells are represented by 1; Trifid's real, irregular dust-lane pattern is 3 clean
  radiating cuts; Crab's smooth-synchrotron-core-vs-noisy-filament-shell distinction is
  approximated via density-weighted colour mixing rather than spatially-varying noise (a named
  simplification, not attempted this session — would need per-region noise amplitude, a real,
  separate piece of work).
- **Visual correctness (does each shape actually read as its real object) is not owner-eyes
  confirmed here** — automated coverage proves the shapes compile, execute cleanly on real
  hardware, and produce nonzero density in the expected regions (torus centreline, ellipsoid
  interior, etc.), but not that the composited result looks right on a real screen.
- **The Helix/ngc7293 duplicate-catalog-entry issue found in Part 3's investigation was NOT
  fixed** — `ngc7293` (curated, 655 ly) and `ngc2000-helix-nebula` (bulk pipeline, 450 ly) are
  two separate travelTo destinations for the same real object. Left as a named, real,
  pre-existing data-quality issue outside this session's scope (a data-hygiene task with its own
  design questions — which entry to keep, whether other such duplicates exist — not a rider on
  this shape/reveal redesign).
