## (1) Destination-gated nebula reveal

Root cause was a design property, not a bug: the volumes were always-on sky features, so
selecting a nebula turned the camera toward already-visible gas. Fix: a per-volume **reveal
envelope** (`NEBULA_REVEAL`, pure and unit-pinned in `nebula-field.ts`):

- 0 through idle, aim, accel, and flip (reveal starts at the HUD's own decel threshold k=0.53 —
  shared constant, so hull/HUD/gas can't drift apart);
- smoothstep ramp to `decelMax` (0.7) across the decel burn;
- ease-out swell to 1.0 over 1.8 s after the ship stops ("enlarge when the ship stops" — density
  scales with reveal, so fringes grow outward rather than a flat crossfade);
- damped fade-out on departure; reduced-motion snaps.

Plumbing keeps ADR-0004's no-uniform-arrays rule: one `vec4 uReveal`, component per volume,
swizzle baked by the generators. Verified on real WebGPU with staged screenshots: accel
`[0,0,0,0]` (pure star field), decel `[0.438,…]` (gas fading in), arrived `[1,…]` (full volume).

## (2) The ship track — what was reused vs new

- **GLB + tier policy reused:** the same `sci-fi-fighter-{1k,2k}.glb` assets and `craft-tier.ts`
  resolution (URL param → stored override → device signals; "off" respected) the live engine
  ships. Loaded via `@babylonjs/loaders` glTF 2.0 (new dep, lazy chunk ~100 KB gz on the ship
  path only), normalized to a unit box under a wrapper whose +Z is the nose (Babylon's RH→LH
  glTF import negates the unit-ship −Z nose onto +Z — `babylon-ship.ts` header).
- **Plume math reused verbatim:** `PLUME_ENGINES`, `buildPlumeVertices`,
  `plumeFlareLength/Alpha/Throttle`, `PLUME_CORE/SHEATH` from ship-dynamics.ts; colours baked
  into the GLSL/WGSL twins. Noise is procedural in-shader (the live engine pre-generates a
  texture — same look, no texture plumbing).
- **New choreography:** the hull materialises at the virtual-ship position the chase camera has
  trailed since B2 step 4 and performs a real **180° flip-and-burn** across the HUD's flip
  window (`flipPhase`, threshold-pinned by unit test) — the decel burn is a genuine retro burn,
  plume toward the destination, exactly when the nebula reveal begins.
- **Heat shimmer (the F3-deferred post-pass):** screen-space refraction PostProcess (GLSL/WGSL
  twins) displacing around the nozzle's projected screen position, throttle-scaled;
  zero-intensity degenerates to an exact pass-through.
- **Docking polish:** hold the berth pose 0.45 s, fade out over 1.2 s (`dockFade`) as the
  dossier takes over; goHome flies the hull back and fades at home.

## Defects found by verification (all fixed in-run)

1. **CSP blocked the meshopt decoder** — the GLBs are meshopt-compressed and Babylon fetches
   the decoder from `cdn.babylonjs.com`, which `script-src 'self'` rightly refuses. Fixed by
   **self-hosting the identical decoder** (`public/assets/craft/meshopt_decoder.js`, copied
   from the meshoptimizer package the asset pipeline already depends on; prettier-ignored as
   vendored) and pointing `MeshoptCompression.Configuration.decoder.url` at it. The CSP's
   existing `wasm-unsafe-eval` (ADR-0002) already covers its WASM.
2. **CSP blocked GLB texture blobs on WebGPU only** — the glTF loader fetches embedded textures
   via `blob:` object URLs on the WebGPU texture path; `connect-src 'self'` refused them (the
   WebGL2 path passed, which is why CI stayed green while real hardware failed). Fixed:
   `connect-src 'self' blob:` — blob URLs are mintable only by same-origin scripts, so the
   origin surface is unchanged. Recorded in [ADR-0005](../adr/0005-babylon-ship-mesh-track.md)
   and [docs/security](../security/2026-07-19-csp-blob-connect-src.md).
3. **WGSL uniform-control-flow violation in the shimmer** — the zero-intensity early-out
   branched around `textureSample`, which WGSL validates as a hard error (real-hardware console:
   "'textureSample' must only be called from uniform control flow"). Restructured both twins to
   one unconditional sample with the offset zeroing as the pass-through. **The TR-045
   console-assertion caught this before any owner report — second save in two increments.**
   One unit test was rewritten accordingly (it had pinned the now-removed branch); declared per
   the no-unexplained-test-modification rule.
4. **Local-only E2E flake mechanism addressed, not re-documented:** with B3's full load, 4
   parallel SwiftShader scenes exceeded this machine's throughput and a rotating set of Babylon
   travel tests timed out per full run (all passing in isolation — the TR-018/043–046 lineage).
   `engine-select.spec.ts` now runs its tests in order in one worker
   (`test.describe.configure({ mode: "default" })`); other spec files still parallelize and CI
   (workers: 1) is unaffected. Full suite then passed 64/64 first try.

## Honest limits

- **Hull scale/reads are a first pass** — the ship is deliberately sized by the live engine's
  own `shipScaleFactor() × SHIP_WARP_SCALE` (clamped 0.2–2); it reads somewhat small/subtle in
  the captures. Owner taste pass expected (one constant).
- **Shimmer is visually subtle by design** (SHIMMER_STRENGTH 0.011 over a 0.16-uv radius) and
  was verified compiled + parameterized + console-clean, not isolated visually — it overlaps
  the plume's own turbulence, which is the F3 look.
- The flip rotates about the ship's local X (pitch-over); no roll flourish. B5 tiering owns
  per-device particle/step scaling; the plume runs full-tier everywhere for now.
- `?craft=off` disables the hull; travel then behaves exactly as B2 (camera-only) — verified by
  the state machine's `shipState === "ready"` guard, not a dedicated E2E.
