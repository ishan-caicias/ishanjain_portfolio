## Why these two slices shipped together

The implementation plan says so explicitly — "land D6.3's linear pipeline FIRST or in the same
slice" — and the reason is arithmetic rather than organisational: adding an sRGB decode moves every
number in the exposure analysis the Reinhard decision was priced against. Landing them separately
would have meant tuning the gain twice and discarding the first answer.

## Measured before changed — and the instrument was validated first

Astra's §A2.3 table measured the cos-latitude-weighted mean luminance of the shipped surface maps.
Rather than inherit those numbers through a pipeline change that invalidates them, this slice
re-derived them from the real assets. The instrument reproduced Astra's independent measurement
**to three decimals on all nine bodies both covered** (dione 0.605, europa 0.844, tethys 0.407,
rhea 0.381/0.380, venus 0.503, io 0.533, moon 0.575, mars 0.408, ceres 0.554) before any number
derived from it was trusted.

It then found something the brief's table did not report, because A2.3 sampled nine of the sixteen
shipped bodies:

> **Eight bodies clip today, not six.** Saturn (mean output 1.500) and Jupiter (1.207) were never
> in the table. Additive correction to A2.3, not a contradiction of it.

## What shipped

**1. sRGB decode (D6.3.1).** `surfaceTex` is decoded to linear before anything multiplies it;
everything is lit in linear; one encode at output. The exact piecewise sRGB EOTF, not `pow(2.2)` —
chosen so the offline instrument that solved the gain and the shader that ships compute the same
numbers. **The exclusions are the substantive part:** `cloudTex` and `specularTex` are coverage
fractions (Astra validated the cloud map's RAW byte against Earth's real geometric albedo — 7%
closure, vs 33% miss if decoded), and `heightTex`/`normalTex`/`detailTex` carry elevation and
vectors. A blanket "decode every texture" would have silently corrupted four of the five. A unit
test asserts each exclusion.

**2. Opposition surge relocated (D6.1a).** `uAlbedo` is now the surge-free **base** (Bond) albedo
and a new `uSurgeB0` feeds `surge(α) = 1 + B0·exp(−α/2°)` into `refl`, where it physically lives.
The published geometric albedo is reconstructed **exactly** at α = 0 — unit-asserted per body, and
that identity is what makes this a relocation rather than a re-grade. Mars is deliberately absent
(its A_B exceeds its p, so its coefficient would be negative — Astra: "Leave Mars alone").

**3. Reinhard (D6.1b).** `L/(1+L)` immediately before the encode. Asymptotes to 1, so nothing can
clip again; strictly monotonic, so every body keeps its rank.

**4. Exposure gain 3.6 → 1.9 (derived, not tuned).** The old gain was fitted on the only two bodies
that were in range. The new one is **solved** against the plan's own criterion — Moon and Mars
unchanged — now that the decode and the curve have moved everything else.

**5. Tier-aware texture ladder (D6.3.2).** `QualityBudget` gains `planetTexture`. `lite` finally
consumes the 2048 `base` tier — shipped since C4 and fetched by nobody, the delivery plan's B5
item. `full` alone fetches `ultra`; below it the 4-6 MB upgrade is **never requested**, where it
used to be unconditional regardless of tier.

**6. Relief self-shadowing (D6.3.3).** Declared SIMPLIFIED; gated on a body actually shipping
relief, so the twelve bodies with neither height nor normal map are bit-identical.

**7. Per-body atmosphere flag (D6.3.4).** Replaces `uAtmosphere = entry.cloud ? 1 : 0` — a proxy
the call site's own comment asked to remove. Value set is `{earth}` and must stay that way until
the Rayleigh term carries a second body's real optical depths.

## Two real defects caught before they could ship

1. **A literal backtick in the WGSL source**, from an escaped-backtick comment inside the template
   literal — TR-078 Part 5's exact trap, which surfaces only as a shader that silently fails to
   compile. Caught by the existing `uses no BACKTICK inside either shader source` guard on the
   first unit run. The guard earned its keep.
2. **A type error in this slice's own new test** (`WGSL_RESERVED_IDENTIFIERS.includes(id)` against
   a narrow literal tuple) — caught by `astro check`. Worth recording alongside it: my first
   verification command piped `npm run build` through `tail`, which masks the pipeline exit code,
   so `budget:check` ran anyway and the error nearly slipped past. The repo's gate is fine; the
   invocation was mine.

### The two E2E failures, and what the isolation runs established

Full-suite run 1: **106 / 108**, failing `PF-10 C4 arriving at Mars` (`planetSphereReady` false)
and `PF-10 C4.2 arriving at Venus` (`planetSphereBody` null). Both are in the exact subsystem this
slice changed, so they were not written off as the known cumulative-load flake without evidence.
Per CLAUDE.md #27, isolation before re-running:

| Experiment                                                                                                 | Result                                 |
| ---------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| The two specs alone                                                                                        | **2 / 2 pass** (59 s)                  |
| `engine-select.spec.ts` alone (32 tests, 6.4 min)                                                          | **32 / 32 pass**                       |
| The exact preceding prefix — accessibility + craft-assets + craft-ship + engine-select (51 tests, 9.3 min) | **51 / 51 pass**                       |
| **Full suite, run 2**                                                                                      | **108 / 108 — fully green** (13.8 min) |

Run 2 passed **both** run-1 failures and `GAP-17` as well. Notable in the other direction: GAP-17,
the flake that has appeared in every recent TR, **passed in run 1** — so run 1's two failures are a
different signature from the usual one, and the two signatures did not co-occur.

**Conclusion, stated at the strength the evidence supports:** the two run-1 failures are
**intermittent and load-dependent, not deterministic** — they survive neither isolation, nor the
whole 32-test spec file, nor the exact 51-test prefix that precedes them, and did not recur on a
second full run of the identical build. That is the cumulative-load class this repo has documented
since TR-073 and re-confirmed in TR-080/081/082.

**What this evidence does NOT establish**, and is worth being explicit about rather than rounding
up: no A/B against a stashed baseline was run, so "this class existed before D6.1" is inherited
from the prior TRs rather than demonstrated for these two specific specs. The mechanism most
consistent with the observations is that `planetSphereReady` is read **without a poll** immediately
after `planetSphereVisible` flips (engine-select.spec.ts:1685) — and this slice's shader is larger,
so its effect compile is slower under a saturated SwiftShader. That is a hypothesis with a named
mechanism, not a conclusion. **No test was modified to make the suite pass** (CLAUDE.md #15); if
the class recurs on this spec, adding a poll there is the fix, and it should be a named change in
the TR that makes it.

**Full-suite runs this slice: 2 of CLAUDE.md #27's 3-run budget**, plus three cheap isolation runs
that answered the determinism question without spending the third.

## Known limitations

- **The `full` / `ultra-progressive` ladder rung was not exercised by any automated run here.**
  Playwright's SwiftShader environment resolves to `balanced`, so every E2E and every screenshot in
  this TR is the `high` rung. The tier gating is unit-asserted and the ultra path is unchanged code,
  but "does ultra still swap in correctly" is owner-eyes work on real hardware.
- **Earth's surface term brightens ~67%** under the new pipeline. Earth is unreachable until D6.4,
  and its appearance is dominated by the Rayleigh/cloud/glint terms rather than the surface, so this
  is deliberately left to be judged at the geometry it will actually be seen at.
- **Absolute appearance of the other eight bodies** is verified only for rank and non-clipping. That
  Europa "looks right" is an owner judgement no test here makes.
- The self-shadow term is an aggregate darkening, not resolved cast shadows (declared SIMPLIFIED).
