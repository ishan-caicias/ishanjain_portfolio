# TR-019 — PF-07 Ship-v2 Phase 4: Adaptive Quality and Fallback Parity

**Date:** 2026-07-17
**Scope:** [PF-07-spaceship-v2.md](../delivery-plan/PF-07-spaceship-v2.md) Phase 4
**Verdict: OVERALL: READY TO PROCEED**

## What Was Delivered

1. **`src/lib/craft-tier.ts`** — pure, unit-tested tier policy and resolution chain:
   URL param (`?craft=1k|2k|off`, dev/rollback, always wins) → stored user override →
   auto device policy (`?craft=on` or stored `auto`: data-saver, `deviceMemory ≤ 4 GiB`, or
   viewport < 768 px → 1K; else 2K; unknown `deviceMemory` treated as capable) → **off
   (wireframe) when nothing is set — the default stays untouched until the P5 rollout.**
2. **Accessible quality override** — a labeled `<select>` card ("Ship model quality":
   Auto / High 2K / Lite 1K / Off) in the Data & Licenses dialog. Persists to
   `localStorage["ij-craft-quality"]` and applies to the live engine immediately — the
   `craft` attributeChangedCallback swaps tiers or restores the wireframe without a reload.
3. **Fallback parity** — no-WebGL + `?craft=2k` E2E-verified: DOM fallback works, no page
   errors (`_loadCraft` guards on a missing GL context). Reduced-motion behaviour is
   unchanged (existing spec) with craft-specific reduced-motion invariants unit-tested since
   P2/P3.
4. **Tests** — +11 unit (policy matrix: capability, data-saver, low-memory, unknown-memory,
   narrow-viewport, stored parsing, full precedence incl. the pre-P5 off default), +4 E2E
   (`?craft=on` → 2K on desktop, → 1K at 375 px, stored override applies with no URL flag,
   no-WebGL fallback with the flag on).

## Suite-Stability Work (continued from TR-018)

The strict page-load console spec failed once more under full-suite load. The captured
failure was the **readiness precondition** (star-stream HUD text within 15 s), never the
console assertion — zero console errors were detected. Fixes: readiness timeout 15 → 25 s
and file-scoped `retries: 2` (mirroring CI's global setting). A real console error fails
deterministically on every retry, so the spec's actual protection is not weakened.
