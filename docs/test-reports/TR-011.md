# TR-011 — Build Green: Lint/Format Scope Fixes

**Date:** 2026-07-17
**Scope:** `npm run build` failing with 14 ESLint errors (+ 62 masked Prettier failures)
**Verdict: OVERALL: READY TO PROCEED**

## Purpose

`npm run build` (`eslint . && prettier --check . && astro check && astro build`) failed with 14
ESLint errors. Investigation showed none of the 14 were in shipped app code, and that fixing them
would have meant editing files the PF-07 delivery plan requires to stay byte-identical to their
prototype source. The real defect was in the lint/format **scope configuration**, not the code.

## Root Causes (two, one masking the other)

**1. ESLint flat-config ignores are anchored, not gitignore-style (the 14 errors).**
All 14 errors came from `resources/Interactive Outerspace Portfolio/` — untracked PF-07 prototype
reference material that is explicitly excluded from lint (see `eslint.config.js` comment and
[PF-07 delivery plan](../delivery-plan/PF-07-space-portfolio-webgl.md) §1).

The folder used to sit at the repo root and has since moved under `resources/`. `.gitignore` and
`.prettierignore` use gitignore semantics, where a trailing-slash pattern matches at **any depth**,
so both still ignored it after the move (`git check-ignore` confirms). ESLint flat-config `ignores`,
however, are anchored to the config directory — so `"Interactive Outerspace Portfolio/"` stopped
matching once the folder moved, silently pulling ~15k lines of vendor prototype code into lint.

**2. Prettier `endOfLine` vs `core.autocrlf` (the 62 masked failures).**
Because `eslint . && prettier --check .` short-circuits, Prettier had never run. With ESLint fixed,
Prettier flagged 62 files — essentially the entire repo, including untouched files. Verified the
cause by diffing Prettier's output against source: identical once `\r\n` is normalised to `\n`, i.e.
**zero real style drift**. This machine has `core.autocrlf=true`, so files check out CRLF while
Prettier defaults to `endOfLine: "lf"`.

Note this failure is **Windows-local only** — git stores LF, so Linux CI checks out LF and passes.
Both root causes were local-environment defects, not defects in committed code, which is why CI
has stayed green.

## What Was Changed

| File               | Change                                                                                                   | Why                                                                                                      |
| ------------------ | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `eslint.config.js` | `Interactive Outerspace Portfolio/` → `**/Interactive Outerspace Portfolio/` (same for `gaia_datasets/`) | Makes the ignore depth-independent, matching the intent already expressed in `.gitignore`. Fixes all 14. |
| `.prettierrc`      | Added `"endOfLine": "auto"`                                                                              | Prettier accepts the working tree's line endings; git's `autocrlf` still normalises to LF on commit.     |
| `.prettierignore`  | Added `resources/`, `.superpowers/`                                                                      | Untracked reference material (3D model exports) and tool scratch — not ours to format.                   |

No application source, and no test, was modified. Deliberately **not** done: editing the 14
violations in the prototype files, which would have broken the byte-identical-to-source requirement
in PF-07 Phase 1.

## Verdict

**OVERALL: READY TO PROCEED.** The build is green end-to-end and the full suite (8 unit + 30 E2E)
passes. The fixes correct lint/format _scope_ configuration only — zero runtime surface, no app code
or test touched.

## Known Limitations / Follow-up

- **Playwright's `webServer` cannot spawn `npm run preview` on Windows** — it crashes with exit
  `3221226505` (`STATUS_STACK_BUFFER_OVERRUN`) before any test runs. `astro preview` started directly
  works fine, and E2E passes 30/30 against an already-running server (`reuseExistingServer` is on
  locally). Pre-existing, unrelated to this change, and CI-unaffected — but it means `npm run test:e2e`
  needs a preview server already up on this machine. Worth a follow-up.
- `endOfLine: "auto"` accommodates `core.autocrlf=true` rather than eliminating the CRLF/LF split. The
  stricter alternative — a `.gitattributes` `* text=auto eol=lf` rule forcing LF checkout everywhere —
  was not taken, as it would renormalise the entire working tree for a Windows-only symptom that CI
  never sees. Revisit if line endings cause friction again.
