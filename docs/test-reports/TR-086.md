## What this slice had to close

The research plan's §3 instrumentation design: **no analytics services, ever** (ADR-0005 CSP
posture — "the absence of tracking is itself a credential" for this site's audience). What it
asks for instead is entirely first-party: a `cosmos:*`-bus session recorder, a ring buffer
capped in size, a debug overlay behind `?funnel=1` following the repo's existing escape-hatch
convention, and a COPY DIAGNOSTICS button so a remote tester can paste one JSON blob into
chat — this repo's own "solo-owner backend."

## What shipped

**New pure module `src/lib/funnel.ts`** (same split as `perf-telemetry.ts`'s `PerfMonitor` /
`load-progress.ts`'s `StageAggregator`: pure, `now`/`storage`-injectable, unit-testable without
a browser):

- `FunnelRecorder` — records `{event, t, meta?}` entries into an in-memory session, capped at
  `MAX_EVENTS_PER_SESSION` (40), and `persist()`s into a `MAX_SESSIONS`-deep (10) localStorage
  ring buffer (`ij-funnel`), updating its OWN entry in place across repeated calls (matched by a
  monotonic `id`, not `Date.now()` — two recorders created in the same millisecond is a real
  risk, not just a test artifact).
- `resolveFunnelOverlay(urlParam, stored)` — URL → stored → default-off, mirroring
  `resolveEngine`'s shape exactly (this repo's established one-hand-roll-per-callsite
  convention; no shared URL-param helper was introduced).
- Derived-flag helpers matching the research plan's named metrics: `armedToPressMs` (assumption
  1), `accidentalWarpEvents` (assumption 3's residual-risk detector), `zeroResultSearches` (the
  D5 ranking-in-the-wild flag), `isPlausibleSession` (the same instrument-fabrication discipline
  `perf-telemetry` already applies — rejects an empty device block or non-monotone timestamps).

**Naming/scope decision, recorded rather than silently resolved:** the research plan names nine
milestones as `first-X` labels (`first-travel`, `first-search-keystroke`, …). The recorder
stores the underlying **repeatable** action names (`travel`, `search-keystroke`, …) instead —
`vista-dismissed` structurally needs every occurrence to drive the accidental-warp detector (a
click right after a **later** dismissal, not just the first), and deduping `travel`/
`search-keystroke` to one entry each would make that detector and the zero-result-query flag
unable to see anything past the first session action. `firstEventTime()` recovers the plan's
exact "first-X" semantics on demand. The four genuinely one-shot gate milestones
(`dossier-visible`, `launch-armed`, `launch-pressed`, `cinematic-done`) ARE deduped to their
first occurrence.

**New `src/components/islands/space/FunnelOverlay.tsx`** — the `?funnel=1` debug overlay:
timeline, the three derived flags, and COPY DIAGNOSTICS (`{funnel, perf}` — reuses
`window.__ijPerf()` rather than re-deriving a device signature). Tailwind utility classes only,
**zero runtime `style` props** — unlike the pre-existing `?perf=1` overlay it sits beside (which
is entirely inline-styled), this component needed no CLAUDE.md #12 workaround because it has no
dynamic-width bars or similar to inline in the first place.

**Wiring in `SpaceScene.tsx`:** the recorder is created once, always running (same convention as
`window.__ijPerf()` — recording is never gated, only the **visible** overlay is), and exposed
programmatically as `window.__ijFunnel()` for the same reason `__ijPerf()` is: this repo's
established E2E pattern for debug hatches is to test the programmatic surface, not scrape
overlay DOM. Milestones are recorded at the existing `cosmos:*` listeners and UI callbacks —
`cosmos:ready` → `launch-armed` (it already **is** the `armed` flag PreFlight renders from — no
separate signal exists to add), `onLaunch` → `launch-pressed`, `cosmos:select`'s non-quiet
branch → `travel` (see "a real bug" below for why not `cosmos:warp`), `cosmos:arrive`'s
non-quiet/non-already-parked branches → `arrival`, the vista's 5.5s auto-timeout and the
`onOpenCard` handler → `vista-dismissed` (with `meta.via`), `onCmdChange` → `search-keystroke`
(query + synchronous result count), the search Enter/suggestion-click paths → `search-travel`. A
defensive `cosmos:ascent-done` listener records `cinematic-done` — additive, so D1.3 needs no
further change once it lands and starts emitting that event; until then it simply never fires.

## A real bug found by React itself, before any test ran

The first hand-written `useEffect` (recording `search-keystroke` reactively off
`state.cmd`/`suggestions`) crashed the ENTIRE scene on every load: **React error #310**
("rendered more hooks than during the previous render"). Root cause: `SpaceScene.tsx` has a
pre-existing `if (!engineReady) return null;` early exit inside the component body (line ~797
before this slice), and the new effect was placed **after** it, in the render-body section where
`suggestions` is computed — so the hook only ran once `engineReady` flipped true, one more hook
call than the first render made. Caught by a throwaway `page.on("pageerror")` probe before
wasting a full E2E cycle chasing a symptom (`waitForSelector("babylon-scene")` timing out with
no other information) — read what the failing system actually says, per this repo's measurement
discipline. **Fixed** by extracting the suggestion computation into a top-level
`computeSuggestions(cmd)` function and recording `search-keystroke` synchronously inside the
existing `onCmdChange` callback instead of a new effect — no hook added, no ordering risk, and
arguably a better design (the query and the result count it actually produced are now computed
together, rather than the effect racing a stale `suggestions` closure).

## A second real bug: `cosmos:warp` cannot detect its own start

The original design recorded `travel` on the first `cosmos:warp` event where `state.warp` was
still null. This never fired for ANY journey: `cosmos:select`'s own handler is what sets
`state.warp` to the `"aim"`-phase object, and by React's next render `stateRef.current.warp` is
already that object before the first `cosmos:warp` tick ever arrives (TR-081: `cosmos:warp`
fires once per rendered frame for the whole journey, not once at its start). **Fixed** by moving
the record call to `cosmos:select`'s non-quiet branch — the actual one-shot "a journey started"
signal, and if anything a more accurate timestamp for the accidental-warp detector than a later
`cosmos:warp` tick would have been.

## A pre-existing UI collision this slice's E2E is the first to exercise

`#ij-mission-bar` (z-62) visually overlaps `ArrivalVista`'s button row (z-61) at the bottom of
the viewport. A real Playwright coordinate-based click on OPEN COLLECTOR CARD — even with
`force: true`, which only skips Playwright's own actionability pre-check, not the browser's real
hit-testing — lands on the WHERE-TO input instead. No existing spec had ever clicked that button
before this slice. Worked around in the new E2E spec with a direct `element.click()` dispatch
(bypasses the coordinate hit-test, still exercises the real `onClick` handler); **not fixed
here** — it belongs to D4.1's vista-dismissal rework, which replaces this whole interaction
(click-anywhere/Space/Escape dismissal, a real `role="dialog"` surface). Handed to that slice
below.

## Known limitations

- `cinematic-done` has no live source yet — the `cosmos:ascent-done` listener is wired but D1.3
  hasn't shipped. No action needed when it does; this is the intended additive handoff.
- `vista-dismissed` currently only distinguishes `via: "timeout"` and `via: "open-card"` — D4.1
  will add `via: "click-anywhere"` / `"space"` / `"escape"` once that slice's real dismissal
  paths exist; today's two paths are the only two that exist to instrument.
- The zero-result-search flag and the accidental-warp detector are unit-tested against synthetic
  event arrays but not separately E2E-asserted in real time (a genuine 1s-apart accidental-warp
  race would need contrived timing in a real browser, judged not worth the wall-clock budget —
  the pure derived-flag functions carry the correctness burden instead, same reasoning TR-085
  used for the stall detector).
- COPY DIAGNOSTICS is verified to produce a valid, parseable JSON blob with real funnel + perf
  content; it is not verified against real remote-tester usage (no such usage exists yet — this
  slice ships the mechanism, not evidence of the process working end-to-end with a human).
