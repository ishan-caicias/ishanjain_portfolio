## What shipped

- **`babylon-asteroids.ts` (pure):** deterministic belt construction (torus spawn, tangential
  drift, spin, mass ∝ scale³), tier-gated counts (48 full / 20 reduced — reuses craft-tier's
  audited device signals, no second policy), seeded rock-vertex displacement (direction-keyed so
  welded vertices stay watertight), the **belt-pull herding acceleration** (toward the spine
  _circle_, not the centre — preserves the ring and guarantees ongoing encounters in zero-g),
  the visual-tier Euler integrator, and the standard WASM-SIMD probe.
- **Engine wiring:** `_setupPhysics` builds the render side first (4 displaced-icosphere base
  rocks, instanced per body, plus the scene's **first light** — a dim hemispheric that the
  custom-shader layers ignore and the PBR hull benefits from), then gates physics:
  SIMD-supported → Havok WASM (fetched same-origin via a Vite `?url` asset — never a CDN, per
  ADR-0005's stance; CSP `wasm-unsafe-eval` from ADR-0002 covers instantiation), zero-gravity
  world, one sphere-shape `PhysicsAggregate` per rock with seeded velocities. No SIMD /
  init failure / reduced motion → the same field in kinematic (or static) visual mode.
  Everything async + failure-tolerant; physics can never blank the sky.
- **Per-frame:** the weak belt pull is applied as a real force (accel × mass) on the Havok tier;
  Havok integrates. Visual tier runs the pure Euler integrator.

## Defect found by verification (fixed in-run)

`Mesh.createInstance()` threw **"InstancedMesh needs to be imported before…"** — the class
module is a required **side-effect import** (it patches the factory onto `Mesh`) and a type-only
import erases. Same tree-shaking trap class as TR-046's `engine.computeShader`. Two fixes: the
side-effect import, and `_setupPhysics` now wraps its whole body so _any_ throw lands in a
terminal `"failed"` state rather than stranding `"loading"` forever (which is exactly how this
bug presented to the E2E poll). One unit-test tolerance was corrected in-run (mass ∝ scale³
compared beyond `Float32Array` storage precision — test bug, declared).
