## Root causes (from the owner's own failure artifacts in `test-results/`)

1. **`:317` GAP-03/04/05 — the test outran its 30s default ceiling, not its assertions.** The
   error context shows the failure at the FINAL `readStats()` (post-`randomBody()`, page
   snapshot mid-acceleration-burn to "GD-1 stream member 54") — every band/constellation/trail
   assertion had already passed. The test's own workload grew with PF-10: boot now competes
   with the SDSS DR18 fetch/decode/mesh build, the DR3 belt, and the bonus star layers, and
   the band's 20-rows-per-frame progressive build is frame-coupled (26 frames; wall-time
   scales with 1/fps under SwiftShader). Same class the B5 tiers test already documented when
   it widened to 90s.
2. **`:1067` distance-scaled travel — a dead-code "reset" masked an under-calibrated poll.**
   The test called `goHome(true)` ~1 ms after `travelTo("sun")` — but `goHome()` is a guarded
   no-op while `warp.mode` is `"aim"`/`"warp"` (babylon-engine.ts:4745), so the reset NEVER
   executed in the test's entire life; the subsequent `warp.mode === "idle"` poll (4s) only
   ever passed because the short Sun journey itself completed in time. At PF-10 scene scale
   the journey's wall-clock stretches past 4s (the per-frame-dt-clamped progress integration
   TR-066 already investigated and documented for the reduced-motion test, widening 2s → 8s).
   The owner's failure snapshot shows exactly this: "ARRIVAL CONFIRMED — The Sun" at poll
   expiry.
