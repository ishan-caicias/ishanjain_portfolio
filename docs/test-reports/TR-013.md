# TR-013 — Playwright webServer Windows Spawn Fix

**Date:** 2026-07-17
**Scope:** Follow-up to [TR-011](TR-011.md) Known Limitations — `npm run test:e2e` standalone on Windows
**Verdict: OVERALL: READY TO PROCEED**

## Purpose

TR-011 recorded that Playwright's `webServer` could not spawn `npm run preview` on Windows,
crashing with exit `3221226505` (`0xC0000409`, `STATUS_STACK_BUFFER_OVERRUN`) before any test
ran, while `astro preview` started directly worked fine. E2E runs on this machine required a
pre-started preview server.

## Investigation

Reproduction was attempted first, from a genuinely clean state (port 4321 confirmed free):
the suite **passed 30/30 with the original `npm run preview` command**. The crash is therefore
**intermittent**, not deterministic — consistent with known Windows failure modes in the
`npm.cmd`/`npx.cmd` shim spawn path (console-handle inheritance under nested spawns), and
possibly aggravated in the TR-011 session by a half-started orphaned preview process.

Because the failing layer is the cmd shim, the fix removes that layer rather than tuning it.

## What Was Changed

`playwright.config.ts` webServer command:

| Before            | After                                             |
| ----------------- | ------------------------------------------------- |
| `npm run preview` | `node ./node_modules/astro/bin/astro.mjs preview` |

`node_modules/astro/package.json` declares `bin: {"astro": "./bin/astro.mjs"}` — the new command
invokes the identical entry point with no `npm.cmd`/`npx.cmd` shim in the spawn chain. A comment
in the config records why, pointing here.

**CI safety:** CI (`ubuntu-latest`) runs `npm run test:e2e` against a downloaded `dist/`
artifact; `node ./node_modules/astro/bin/astro.mjs preview` is platform-neutral and resolves the
same binary CI already uses through the shim.

## Commands Run / Verification

| Step              | Command / check                         | Result                                                         |
| ----------------- | --------------------------------------- | -------------------------------------------------------------- |
| Clean-state check | `curl http://localhost:4321/`           | Port free before each run                                      |
| Baseline repro    | `npx playwright test --workers=1`       | 30/30 passed (crash did **not** reproduce with old command)    |
| Acceptance        | `npm run test:e2e` (exact task command) | **30/30 passed** (2.1m) — Playwright spawned the server itself |
| Teardown          | `curl` after suite                      | Port 4321 released                                             |
| Lint + format     | `npm run lint`                          | Clean                                                          |
| Type/astro check  | `npm run check`                         | 0 errors                                                       |

## Verdict

**OVERALL: READY TO PROCEED.** `npm run test:e2e` now works standalone on Windows with no
pre-started server, the implicated spawn layer is gone, and CI behaviour is unchanged. This
closes the TR-011 known limitation.

## Honest Caveat

Since the original crash was intermittent and did not reproduce during this session, the fix is
preventative hardening of the implicated layer plus a verified-green acceptance run — not a fix
validated against a live reproduction. If `0xC0000409` ever reappears with the direct-node
command, the shim hypothesis is falsified and the next suspect is the Node/OS layer itself
(Node version, antivirus interference with console spawns).
