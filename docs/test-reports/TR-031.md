# TR-031 — Dev-Mode Hydration Crash (`_jsxDEV is not a function`) & Gate-Procedure Correction

**Date:** 2026-07-18
**Scope:** Owner report — on `astro dev` at :4321, **neither** `?perf=1` nor
`?engine=babylon&perf=1` showed the perf overlay or any graphics; both rendered only the title
and paragraph.
**Verdict: OVERALL: READY TO PROCEED**

## Diagnosis (measured, not inferred)

Driving the owner's live dev server headlessly and capturing console + network:

```
[PAGEERROR] _jsxDEV is not a function
504 (Outdated Optimize Dep) → /node_modules/.vite/deps/@babylonjs_core_Engines_shaderStore.js
[PAGEERROR] Failed to fetch dynamically imported module: /src/lib/babylon-engine.ts
```

The React island **never hydrated** — hence no `<space-engine>`, no `<babylon-scene>`, no
`window.__ijPerf`, no overlay. Only the static SSR HTML rendered, which is why both URLs looked
identical.

**Root cause.** `babylon-engine.ts` is a **lazy dynamic import**, so Vite's dev dependency
optimizer only discovers its many deep `@babylonjs/core` subpath imports when
`?engine=babylon` is first opened. That late discovery triggers a mid-session re-optimize, which
504s the in-flight module graph and takes React's JSX dev runtime with it — breaking hydration on
**every** route, not just the Babylon one. Adding `@babylonjs/core` and then repeatedly changing
its subpaths across B0/B1 is exactly the churn that provokes this.

**Ruled out:** duplicate React (`npm ls react react-dom` → single deduped react@19.2.7), and any
production defect (the build was green throughout — 52/52 E2E on `astro preview`).

## Fix

`vite.optimizeDeps.exclude: ["@babylonjs/core"]` in [astro.config.mjs](../../astro.config.mjs).
Babylon ships clean ESM, so excluding it from the optimizer means **no re-optimize can ever be
triggered** by loading it. Chosen over `optimizeDeps.include` (which would need the subpath list
kept in sync as B2+ adds loaders/post-processes — a silent-regression trap). Cost: the
`?engine=babylon` page loads more slowly in `astro dev` only; production builds are bundled by
Rollup and unaffected. Stale `node_modules/.vite/deps` also cleared.

## Second finding — the gate procedure was measurable-but-wrong on dev

The owner was about to take gate readings on `astro dev`. **Dev numbers are invalid**: measured on
the same machine, startup was **3517 ms (dev) vs 843 ms (preview)** — a ~4× distortion that could
sink an otherwise-passing engine. The
[gate procedure](../validation-checklist/2026-07-18-pf09-b1-gate-measurement.md) said
"npm run preview" but not emphatically; it now carries a ⛔ production-build-only banner, a
`window.__ijPerf()` sanity check ("if undefined, the island didn't hydrate — the numbers are not
real"), and reference CI readings.
