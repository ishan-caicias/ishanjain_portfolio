# TR-030 — Shiki/CSP Config Warning Resolved

**Date:** 2026-07-18
**Scope:** Build-config warning: _"Shiki syntax highlighting uses inline styles that are not
compatible with Content Security Policy (CSP). Consider using Prism syntax highlighting instead,
or disable CSP if Shiki is required."_
**Verdict: OVERALL: READY TO PROCEED**

## Diagnosis

Astro's config check fires whenever `markdown.syntaxHighlight` is Shiki (the default) **and** a
CSP is configured — regardless of whether any markdown exists. It flagged a genuine conflict with
this project's strict hash-based CSP (TR-010/TR-016 lineage), since Shiki emits inline styles that
would require `'unsafe-inline'` in `style-src`.

**Key finding: this site renders no markdown at all.** Verified — no `.md`/`.mdx` under `src/`,
no content collections (`src/content.config.*` absent), and no `getCollection`/`astro:content`
usage anywhere. The `docs/*.md` tree is documentation outside Astro's pipeline.

## Fix

`markdown.syntaxHighlight: false` in [astro.config.mjs](../../astro.config.mjs).

Astro's suggested alternative (Prism) was **rejected**: it would be equally unused and would
additionally expect a Prism CSS theme to be shipped. Disabling CSP — the other suggestion — was
never an option: the strict CSP is a deliberate OWASP A05 control. Turning the highlighter off
removes dead weight and keeps CSP strict, with a comment recording what to do if markdown is ever
added (choose Prism, or deliberately hash/allow Shiki's inline styles).
