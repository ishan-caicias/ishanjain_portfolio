## TypeScript target decision

The request was "upgrade to TypeScript 7". TypeScript 7.0.2 is the current `latest` stable tag,
**but the project's TypeScript-consuming tooling does not yet support it**:

- `@astrojs/check@0.9.9` (the `npm run check` typechecker) → peer `typescript: ^5 || ^6`
- `typescript-eslint@8.63.0` (typed linting) → peer `typescript: >=4.8.4 <6.1.0` (no released or
  canary version supports 6.1+)

Installing TS 7 would break both `check` and `lint`. Per the user decision, the project was
upgraded to **TypeScript 6.0.3** — the highest version the toolchain fully supports — pinned as
`~6.0.3` so a future 6.1 cannot silently violate the typescript-eslint ceiling. TS 7 adoption is
a tracked follow-up (see ADR-0001, "Follow-up").

## OWASP audit outcome

Full findings and rationale: [security/2026-07-13-owasp-audit-and-hardening.md](../security/2026-07-13-owasp-audit-and-hardening.md).
Implemented in this pass:

- **A05 Security Misconfiguration** — added a hash-based Content-Security-Policy (Astro
  `security.csp`) and a `public/_headers` file (nosniff, HSTS, X-Frame-Options, Referrer-Policy,
  Permissions-Policy, COOP/CORP).
- Refactored `space-engine.js` to stop injecting an inline `<style>` at runtime (moved the
  `<space-engine>` focus outline into `global.css`) so the hash-based CSP needs no `unsafe-inline`.
- **A06 Vulnerable Components** — 0 CVEs (above).
- Confirmed clean (no change needed): no XSS sinks (`set:html`/`dangerouslySetInnerHTML`/`innerHTML`/
  `eval`), all external links carry `rel="noopener noreferrer"`, no secrets in source.

## Known limitations

- `public/_headers` is honored by Netlify and Cloudflare Pages. Vercel needs `vercel.json`;
  GitHub Pages cannot set custom headers (the `<meta>` CSP still applies). See the security doc.
- CSP is emitted only on `build`/`preview`, not `astro dev` (Astro/Vite limitation) — expected.
- TypeScript held at 6.0.3 pending ecosystem TS7 support (tracked in ADR-0001).
