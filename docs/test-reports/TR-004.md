## What Changed

### Real bugs found and fixed (via new/updated e2e coverage, not just written to pass)
1. **[HUD.tsx](../../src/components/islands/space/HUD.tsx) - `aria-hidden="true"` hid the travel/scroll mode toggle button from assistive tech.** The right-side HUD readout wrapper had `aria-hidden="true"` on the whole block, which also swallowed the interactive "◈ CLASSIC VIEW / ◈ TRAVEL MODE" `<button>` inside it - a real, keyboard-focusable control that screen readers couldn't announce. Fixed by moving `aria-hidden` onto just the decorative bearing/sector/status text, leaving the button in the normal accessibility tree.
2. **[HUD.tsx](../../src/components/islands/space/HUD.tsx) - HUD controls had no `z-index`, so roaming station sprites (`z-index: 5`) could paint over them and block clicks.** Reproduced via e2e under real timing (not synthetic): a station sprite (`LET'S CONNECT` / `SIRIUS · 8.6 LY`) intercepted a click meant for the CLASSIC VIEW button because the HUD's top-left/top-right containers had no explicit stacking order. Fixed by giving both HUD containers `z-10`, above `StationSprites`' `z-5` and below every overlay/dialog layer (60-90) already established in the space component z-index scale.
3. **`eslint.config.js` / `.prettierignore` never accounted for non-source content added across PF-07** (the untracked 39MB prototype folder, the untracked 1.6GB `gaia_datasets/` raw pipeline dump, and the Phase-1 verbatim-ported `space-engine.js`/`celestial-*.js` files that must stay byte-identical to source) **or pre-existing gaps** (`.claude/`, `coverage/` - both already gitignored but never added to the manually-maintained lint ignore lists). `npm run lint`/`npx prettier --check .` were effectively unusable for the whole repo (1000+ false-positive errors, and prettier OOM-crashed on the 1.6GB dataset folder). Fixed by adding explicit ignores to both files; scoped-to-changed-files lint checks in TR-001/002/003 had been silently working around this rather than fixing it.
4. **`scripts/coverage-report.mjs:70`** - pre-existing unused-variable lint error (confirmed present on `main` via `git log`), unrelated to PF-07. Trivial one-line dead-code fix, folded in since it was blocking the now-working full-repo lint.

- **Deleted `tests/e2e/star-interaction.spec.ts`** - tested the old `Starfield`/`StarModal` system (`/hubble/data.json`, `starclick` events), which `Hero.astro` no longer mounts as of Phase 4. All 4 of its tests failed with timeouts against the real homepage.
- **Added `tests/e2e/space-scene.spec.ts`** (10 tests) covering the handoff doc's §4 testing checklist: scene mount + live catalog data + console-clean, travel-mode-by-default, nav-link → warp → dossier open, dossier close (button + Escape), RNG travel, travel/scroll toggle, a dedicated WebGL-fallback suite (stubs `getContext` via `page.addInitScript`, confirms `_domFallback()` engages and navigation still works via the engine's `noGL` branch), and a reduced-motion suite (`page.emulateMedia`, confirms the engine's own `.reduced` flag and `global.css`'s blanket `prefers-reduced-motion` CSS rule both engage).
- **Updated `tests/e2e/navigation.spec.ts` and `tests/e2e/accessibility.spec.ts`**: fixed stale content assertions that pre-dated PF-07 and were already broken on `main` (hero copy substring, credibility card copy, h1 text - confirmed via `git diff main` that these test files are byte-identical to `main`, i.e. these were latent pre-existing failures, not introduced by this branch). Adjusted "clicking nav link scrolls to section" and "semantic landmarks are present" to switch to classic/scroll view first, since travel mode is now the default nav experience and hides the scrollable sections/footer by design.

- Mobile viewport (375×812, DPR 2): scene mounts, zero console errors, zero failed requests.
- WebGL fallback (`_domFallback()`): verified via a real e2e test (not just source reading) that stubs `HTMLCanvasElement.prototype.getContext` to return `null` for WebGL contexts before navigation. Confirmed `cosmos:ready` still fires, HUD reaches its `ONLINE` state, and clicking a nav link still opens the correct dossier via the engine's `noGL` branch of `travelTo()` (immediate quiet arrival, no render).

## prefers-reduced-motion Audit

- Confirmed both layers respect it: `space-engine.js` reads `matchMedia('(prefers-reduced-motion: reduce)')` once at connect and halves/shortens aim/warp/idle-drift durations throughout; `global.css`'s pre-existing blanket rule (`*, *::before, *::after { animation-duration: 0.01ms !important; ... }`) already covers every DC-layer keyframe added in Phases 2-4 (`ij-cardin`, `ij-drift`, `ij-tumble`, etc.) with no additional CSS needed.
- Tooling note: Playwright's `test.use({ reducedMotion: 'reduce' })` context option did not reliably apply before the first navigation in this environment (reproduced with a minimal standalone probe, unrelated to this app's code); calling `page.emulateMedia({ reducedMotion: 'reduce' })` explicitly before `page.goto()` is the reliable equivalent and is what the test uses.

## Known Limitations / Carried Forward

- The full e2e suite is resource-heavy under this app's real-time WebGL engine (168K+ objects); a temporary local repro with 8 parallel workers against a **stray `astro dev` server left running on the same port** produced flaky/wrong results (Playwright's `reuseExistingServer` silently reused it instead of the configured `npm run preview` production build). Not a real bug - documented here so a future session doesn't re-chase it. CI already forces `workers: 1` via `playwright.config.ts`, so this doesn't affect CI reliability.
- `tests/unit/StarModal.test.tsx` and `tests/unit/Starfield.test.tsx` still have their own pre-existing unused-var lint errors; both files (and their tests) are removed in Phase 6 per the delivery plan, at which point these resolve automatically.
- Lighthouse was not run (no CLI harness configured in this repo); bundle-size/lazy-load numbers above were measured directly via live network inspection instead, which covers the same exit-criteria question (initial payload size, DSO lazy-load behavior).
