## What shipped

New pure module `src/lib/celestial-bodies.ts`, wired into `babylon-engine.ts`
per the gap analysis's implementation guardrail (ported rules into a new
Babylon-side module rather than touching the archived, frozen
`space-engine.js`; one shared billboard-quad primitive for both passes, not
two parallel systems):

**GAP-01 — procedural beacons.** Every `window.CELESTIAL` entry (~2,525 at
catalog scale: 2,500 curated + a small Gaia top-up) that lacks a photo cell
renders as a per-type shaded billboard, ported from `space-engine.js`'s
`STAR_VS`/`STAR_FS` "beacon" mode (its `uMode>0.5` branch — distinct from the
field-star mode the same shader also drives): star (diffraction spikes +
pulse), planet/moon (lit disc + limb darkening), nebula (3-lobed cloud),
galaxy (inclined disc + nucleus), globular/open cluster (grain/scatter), deep
field (speckle), black hole (photon ring + lensed arcs — no current catalog
entry uses this type, but the shader path exists and is unit-tested).

**GAP-02 — photographic billboards.** The 267-body subset with a cell in the
already-shipped `public/assets/atlas.jpg` + `atlas-map.json` (the archived
engine's own pre-composed "fast path" atlas — self-hosted, same-origin, no
new asset shipped) renders textured: NASA/ESA imagery for DSOs with the
radial vignette + Hubble-flow redshift tint, and a lit, slowly rotating globe
for planets/moons with Saturn's ring band. Ported from `PHOTO_VS`/`PHOTO_FS`.

Both passes: GLSL + WGSL shader twins, corner derived from the vertex id
(reusing `star-field.ts`'s B2 vertex-expansion convention — no stored corner
attribute), additive blend matching the archived engine's single global blend
state (`SRC_ALPHA, ONE` — vignette/falloff is baked into colour, not relied
on via alpha, precisely so additive hides the quad's edges).

## A real bug the guardrail's own TDD step caught before it reached a browser

The first draft of the photo fragment shader branched on body type
(`if (ty < 1.9) { ...textureSample()... } else { ...textureSample()... }`)
before sampling. WGSL forbids `textureSample` in non-uniform control flow —
`ty` is constant across one body's quad but differs between bodies drawn in
the same call, exactly the class TR-047 fixed on the ship's heat-shimmer
pass. Restructured to compute both candidate UVs, select one arithmetically,
sample **once, unconditionally**, then branch only on the already-sampled
colour. A new test (`tests/unit/celestial-bodies.test.ts`, "TR-047 guard")
asserts exactly one `textureSample(` call in the WGSL source, positioned
before the first `if`. This is the second time this exact defect class has
been caught in this repo (TR-047, now here) — both times before reaching
real hardware, both times because a rule from CLAUDE.md was checked as a
concrete, automated assertion rather than trusted from memory.

## Descoped, named (not silently dropped)

Per the guardrail's "proportionality over completeness" rule:

- **Runtime canvas-composed atlas.** The archived engine's _slow path_
  (composing an atlas from up to 256 individual images at runtime) is not
  reimplemented — this module consumes the already-pre-built `atlas.jpg`
  directly. Visually equivalent; simpler; no code duplicated.
- **Dynamic close-up billboard on arrival.** The archived engine additionally
  fetches a full-resolution individual image for a body that has `img` but
  _no_ atlas cell, on arrival. Not implemented here — such a body (there are
  ~1,000 in the wider 2,500-entry extension, none in the curated 267) renders
  procedurally instead of getting a late high-res swap. A real, lesser scope
  gap; a plausible fast-follow if the owner wants full parity.
- **Relativistic aberration/Doppler on bodies.** GAP-06's dependency — needs
  the flight model's velocity wired to a body pass, not yet done for stars
  either on this path.

empty); the type/appearance rules were **ported** into

shader consumed them.

**E2E note — an environmental blocker, not a code issue.** This machine
currently has Windows TCP ports `4246–4345` excluded
(`netsh interface ipv4 show excludedportrange protocol=tcp` — verified; a
raw `node -e "require('http').createServer(...).listen(4321)"` fails
`EACCES` with **no Playwright or Astro involved at all**), which covers this
repo's hardcoded port 4321. `npm run test:e2e` cannot bind its webServer
right now. Worked around for this pass only: a temporary, uncommitted
Playwright config pointing at port 4400 (outside the exclusion), running the
**real, unmodified** spec files. Result: **70/72 passed**; the 2 failures
are `webgpu-hardware.spec.ts`'s two real-hardware tests, which hardcode
`BASE_URL = "http://localhost:4321"` as an internal constant independent of
Playwright's `baseURL` fixture (by design — that file's own header explains
why it stays out of the shared config) — those 2 tests would pass under the
standard command once port 4321 is free again, and are unrelated to this
change. Re-run twice for stability; one accessibility test flaked once
under the workaround config's non-standard server-reuse pattern and passed
clean on both the isolated re-run and the second full pass. **Recommended
follow-up for the owner:** re-run `npm run test:e2e` normally once this
machine's port exclusion window rotates (these are dynamic Windows/Hyper-V
reservations that clear on their own, typically within hours, or immediately
after a reboot) to get the standard-command confirmation on record.
