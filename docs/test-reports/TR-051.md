# TR-051 — B5 code-complete: the formal quality-tier system

**Date:** 2026-07-19
**Scope:** B5 (responsiveness & quality tiers), 5milestone scorecard governs. One unified tier
system replaces the per-feature ad-hoc quality knobs accumulated through B2–B4.
**Verdict: OVERALL: READY TO PROCEED** — 216/216 unit · 66/66 E2E · build/lint/typecheck exit 0
· real hardware: `full` tier resolved and asserted on real WebGPU; `lite` override verified
end-to-end (all budgets applied, coherent scene, clean console). **B5's real-device exit rows
for mobile remain gated on the owner's devices** — same convention as B2's open condition.

## What shipped

- **`babylon-tiers.ts` (pure):** `resolveQualityTier(backend, deviceTier, override)` → one of
  three named budgets (`full` / `balanced` / `lite`) covering star halo (the live engine's own
  0 / 0.55 / 1 values, finally honoured on the Babylon path), shooting-star count (24/16/8),
  nebula raymarch step scale (1 / 0.7 / 0.5) and offscreen texture scale (0.5 / 0.4 / ⅓),
  asteroid-body count (48/32/20), and the shimmer post-pass (off on lite). Inputs are things
  the repo already measures: the engine's own WebGPU→WebGL2 backend result and
  **perf-telemetry's `classifyDeviceTier`** — one device policy, not two. `?tier=` overrides
  for testing/rollback (the `?craft=` pattern). Budget-table mapping: WebGPU high→full,
  mid→balanced, low→lite; WebGL2 high→balanced, else lite.
- **Engine wiring:** resolved ONCE in `_boot` when the backend is known; every knob reads the
  budget — halo uniform, shooting-star build count, nebula generator step counts (generators
  gained a `steps` parameter; the GLSL registration is overwritten with the tier-scaled source
  before the effect compiles), nebula texture scale (setup + resize), asteroid count, shimmer
  creation gate. Badge now shows the tier (`… · LITE · PF-09 B5`) — the same on-device
  discharge instrument ADR-0003's condition 2 used.
- **Deliberate non-tier dimensions:** reduced motion stays a per-feature behaviour contract
  composing with any tier; WebGPU→WebGL2 and no-WebGL/DOM fallbacks remain the pre-existing
  first-class policies beneath the quality dimension; craft 1k/2k stays the asset-resolution
  axis (orthogonal to runtime quality). Touch/pointer parity is inherited via the shared React
  chrome (both engines drive the same UI; free-look drag remains the pre-existing named scope
  boundary from TR-040).

## Honest limits

- Budget VALUES are engineering first-passes; the owner device pass may retune them (one table).
- No runtime adaptive downgrade (fps-reactive tier drops) — tiers resolve once at boot;
  adaptive switching is a possible B6+ enhancement, deliberately not speculated into B5.
- ADR-0003's billboard-memory condition remains open for the B6 cutover (unchanged).
