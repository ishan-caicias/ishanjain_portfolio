# TR-025 — F2 Amendments: 30° Thruster Chase & Ship-Turns Launch

**Date:** 2026-07-18
**Scope:** Owner-directed amendments to [PF-08 F2](../delivery-plan/PF-08-flight-v3.md)
(delivered in [TR-024](TR-024.md)): the v1 flank-swing choreography read as a top view; the
launch should visibly point at the clicked object.
**Verdict: OVERALL: READY TO PROCEED**

## Changes

1. **Chase retune** — `CHASE_WAYPOINTS` replaced: one consistent behind-the-thruster view held
   **exactly 30° above the thrust axis** (`CHASE_ELEVATION`; interior waypoints derive
   `u = −tan 30°·back`, so the interpolated elevation is 30° across k ∈ [0.10, 0.92]), panning
   OUT 2.6 → 5.3 units through cruise/flip and closing to 2.2 for the final approach. Seam
   waypoints (`[0,0,3]` at k = 0 and 1) unchanged — launch/arrival continuity preserved.
2. **Launch points at the click** — the aim phase no longer eases the camera onto the target.
   `_warpDir` is set at `travelTo`/`goHome` time and the ship's orientation damp (extended to
   the aim phase) turns the ship toward the route — which on screen is exactly where the
   clicked object sits — while the view holds still; the chase look then pans after the ship
   during the burn. The now-dead camera pre-aim fields (`fromYaw/toYaw/toPitch` + wrap math)
   were removed from the warp state.
3. **Deliberate test modifications** (per the amendment, each named):
   - unit `"actually swings the viewing angle: side views on both flanks"` → replaced by
     `"holds the camera 30° above the thrust axis"` and `"pans out through cruise/flip"` —
     the flank-swing behaviour it asserted was the thing the owner retuned away.
   - E2E `flight-v3.spec.ts` rewritten: the three flight-model specs now drive `_tick` with
     synthetic 60 fps timestamps and a stations-ready gate (see Flake investigation); the
     mid-warp look-pan assertion moved from wall-clock sampling to full-journey frame capture.

## Flake investigation (why three E2E runs differed)

1. **Dev-server reuse**: `reuseExistingServer: !CI` made the suite reuse the session's running
   astro **dev** server (HMR client noise, slower) — 4 spurious failures. Resolution: stop dev
   servers before suites.
2. **Hydration race** (pre-existing, now visible): clicking a nav link before SpaceScene calls
   `setStations()` makes `travelTo` a silent no-op — journey never starts. Specs now gate on
   stations registering; product-side queueing spun off as its own task.
3. **FPS starvation**: 3–4 parallel WebGL pages drop to single-digit fps — the 144 ms flip
   window falls between frames and both protocol round-trips and in-page 40 ms timers starve.
   Resolution: flight-model specs drive the engine clock synthetically (real engine, simulated
   60 fps); click-through UI coverage stays wall-clock in `space-scene.spec.ts`.
4. **Leaked preview servers**: three `astro preview` process pairs accumulated across
   interrupted runs and degraded later runs; killed. Post-cleanup: **48/48**.
