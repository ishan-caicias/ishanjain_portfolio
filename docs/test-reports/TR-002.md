## What Was Verified (live browser)

The preview browser tab runs backgrounded (`document.hidden === true`), which throttles
`requestAnimationFrame` and froze the WebGL engine's own internal warp animation at `t=0`. This is
a testing-harness characteristic, not an application bug — Phase 1's TR-001 already confirmed the
engine renders and animates correctly when the tab is visible. To verify Phase 2-3's React state
machine independent of rAF timing, verification used a mix of real interaction (RNG button click,
button clicks) and direct `cosmos:*` custom-event dispatch to exercise the same code paths
deterministically:

- **HUD**: real catalog data rendered — `ONLINE · 168,959 LIVE SOURCES · 2525 CHARTED`, correct
  bearing (`RA 03h 00m · DEC −8.0°`), correct sector/status labels.
- **Mission control**: RNG button triggered a real `cosmos:select` → `warp` state transition;
  `WarpOverlay` correctly resolved and displayed the destination name (`NGC 752`) via `entryFor()`
  and the "ALIGNING TRAJECTORY" phase label.
- **SectionOverlay**: "DATA & LICENSES" button opened the Credits panel with all 18 attribution
  rows rendering exact source text; DOSSIER ↔ CONSOLE variant switching confirmed via DOM class
  inspection (correct `animate-[ij-slidein...]` vs. `animate-[ij-cardin...]` classes applied).
- **CollectorCard**: synthetic `cosmos:arrive` dispatch to `m42` (Orion Nebula) rendered a complete,
  correct dossier — rarity gems (`◆◆◆◆◆` for legendary), all 6 stat rows, field note text verbatim,
  both sky-lore entries (Maya, Aboriginal Australian) with correct culture tags, and the real NASA
  image (`assets/dso/M42.webp`) loaded with **zero failed network requests**. Confirmed the
  "re-arrival at the same body opens the dossier directly" branch (`!s.warp && s.arrivedId === id`)
  fires correctly on a second arrival at the same id — exact source behavior, not a simplification.
  Verified all 3 card style variants (holo/dossier/plate) switch correctly via DOM class inspection.

## Issues Found and Fixed During This Phase

| Issue | Fix |
|---|---|
| `KeyboardEvent` dispatched on `document` never reached the app's `window`-level Escape listener during manual testing | Test-harness bug, not an app bug: `new KeyboardEvent(...)` defaults `bubbles: false`. Fixed by adding `bubbles: true` to the synthetic event. |
| Forgot to wire the `ij-barin` letterbox-bar animation onto `WarpOverlay`'s top/bottom bars | Added `animate-[ij-barin_0.5s_ease-out_both]` to both bar `div`s before browser verification. |
| `space-test.astro` didn't import `global.css` | Tailwind utility classes and the new `ij-*` keyframes would not have applied at all (unstyled HTML) - added the import. |
| Content duplication risk | `Credibility.astro`'s inline array and `Achievements.astro`'s local icon map were about to be duplicated a third time inside `SpaceScene`. Extracted to `src/content/credibility.ts` and `src/content/icons.ts`, both existing components now import from the shared source instead. |

## Known Limitations (by design, deferred to Phase 4)

- Mission-control bar is fixed-position, not tethered below the spaceship each frame.
- No station sprite markers, no header/footer nav integration, no scroll-mode fallback.
- `_sprTick`'s astronaut-mascot and hero-copy "dodge zone" positioning not ported (no DOM target
  exists for them yet in this standalone test page).
- E2E coverage for the space scene not yet written — Phase 5.
