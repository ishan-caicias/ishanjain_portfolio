## Why this exists

ADR-0010 (2026-07-22): automatic device tiers stop being the ceiling and become the default
preset. A visitor multi-selects which DSO/celestial layers render, independent of what their
device would otherwise be limited to. This is the last of PF-11's five owner decisions to
land as code (D3.3/D6.1/D5.1/D4.4 shipped earlier in the plan; D6.2 shipped in TR-109).

## D9.1 — Layer registry + engine surface

New `src/lib/render-layers.ts` (pure, no DOM/Babylon): `LayerId` (11 layers — the implementation
plan's exact list plus `gaia-tiny` for D8 forward-compatibility), `LayerMeta` (bytes, verts,
per-tier defaults, `bootCritical: false`, and a new `implemented` field — see below),
`parseLayersParam`/`serializeLayersParam` (`?layers=id:value,...`), `tierDefaults`,
`resolveLayers` (URL → localStorage `ij-layers` → tier default, matching every other override
surface this repo has), `formatBytes`/`formatVerts` for the panel's cost labels.

**`implemented: false` on 3 of 11 layers — an honest architectural finding, not an oversight:**

- `star-field` — always on by design (ADR-0010's own text: "not toggleable off; it IS the
  scene").
- `bonus-stars` — **merged permanently into the base star mesh** (`_applyStarFieldGeometry`,
  one draw call, one shared material). Toggling it independently would mean keeping the base
  field cached separately and rebuilding without the merge on disable — a real structural
  change, not a `setEnabled` call. Recorded as a follow-up, not attempted this pass.
- `gaia-tiny` — D8 hasn't shipped its data pipeline yet. The registry carries the id and its
  D8-estimated cost (36 MB, 2,552,302 × 4 verts) for forward-compatibility; the panel renders
  it as a disabled row with an explicit "COMING IN A FUTURE UPDATE" label rather than silently
  omitting it or pretending it works.

**`babylon-engine.ts`'s new surface:** `setLayers(config)` (merges + applies only the ids that
actually changed, persists to `localStorage`, emits `cosmos:layers` with the full resolved
state), a new `layers` observed attribute (JSON, same `attributeChangedCallback` pattern as
`density`/`constellations`/`craft`), and `_applyLayerToggle` covering the 6 layers with a real
immediate action:

| Layer            | Mechanism                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sdss-field`     | Enable: fetch (if never loaded) or `setEnabled(true)`. Disable: `mesh.dispose()` + reset the `_sdssLayerRequested` guard so a future enable re-fetches — matching the exit criteria ("disabled + heap drop... re-enable → fetch + progress events") rather than merely hiding a resident 47 MB mesh.                                                                      |
| `belt-visual`    | Same dispose/re-fetch pattern, its own mesh/guard.                                                                                                                                                                                                                                                                                                                        |
| `belt-physics`   | **Not** in `_applyLayerToggle` — read live. `_updateFrameLadder` already calls `_setBeltPhysicsAwake` every frame from the D2.1 distance fade (D7.5); this layer is now a SECOND, independent AND-gate on that same call, so a visitor who disabled belt physics stays disabled even parked at Mars.                                                                      |
| `nebula-volumes` | New `_nebulaLayerEnabled` flag, `mesh.setEnabled()`.                                                                                                                                                                                                                                                                                                                      |
| `gd1-trail`      | Direct `mesh.setEnabled()` — the mesh already existed, had no prior toggle.                                                                                                                                                                                                                                                                                               |
| `constellations` | Reuses the PRE-EXISTING `_showConstellations` flag/mechanism (GAP-12's `constellations` HTML attribute) — this is a second way to reach the same effect, not a competing one.                                                                                                                                                                                             |
| `milky-way-band` | New `_bandLayerEnabled` flag, folded into `_tickMilkyWay`'s existing `uFade = bandFadeAmt × localFieldFade` product as a third multiplicand — not a `setEnabled` call, since the band's visibility was already alpha-driven, not enable-driven.                                                                                                                           |
| `planet-hires`   | **Not** in `_applyLayerToggle` — read live in `_tickPlanetSphere`'s ladder selection, alongside the existing `ladder === "ultra-progressive"` tier gate. Takes effect on the NEXT body dressed, not the one on screen — an accepted v1 limitation (retroactively dropping an already-loaded ultra texture would need its own departure-style disposal, D7.2's territory). |

All three fetch-gated layers (`sdss-field`, `belt-visual`, `bonus-stars`'s absence aside) also
gate their **initial** boot fetch on the resolved layer state — a visitor who loaded with
`?layers=sdss-field:0` never pays for the 47 MB fetch at boot either, not just after opening
the console once.

New `sceneStats().layers` mirrors the full resolved state for E2E/diagnostics.

**19 new unit tests** (`render-layers.test.ts`): registry invariants (unique ids, every tier
declared, `belt-physics`/`planet-hires` defaults mirror `QUALITY_BUDGETS` exactly),
`parseLayersParam`/`serializeLayersParam` round-trips and malformed-input tolerance,
`resolveLayers`'s full URL → stored → tier precedence including partial overrides and
malformed-JSON/non-object localStorage values.

## D9.2 — RenderConsole.tsx panel UI

New `src/components/islands/space/RenderConsole.tsx`: dossier-format dialog matching the DATA
& LICENSES precedent (`SectionOverlay.tsx`'s `credits` section) — same panel classes, same
close-button/header layout. Talks to the engine only through `sceneStats()`/`setLayers()`,
the same arm's-length pattern `CraftQualityControl` (also in `SectionOverlay.tsx`) already
uses for the ship-quality override — no direct engine internals.

- **Rows:** one per `LAYERS` entry — checkbox for boolean layers, number input for
  `belt-physics`/`gaia-tiny` (count-typed), disabled checkbox + explanatory text for the 3
  `implemented: false` layers, all with the real byte/vertex cost label.
- **Presets:** LITE/BALANCED/FULL apply `tierDefaults(tier)` to every implemented layer in
  one `setLayers` call; EVERYTHING forces every implemented boolean layer to `true` (and uses
  `full`'s own `belt-physics` count, since exceeding the boot-built Havok body count needs a
  world rebuild, out of scope here) — never touches the 3 not-yet-implemented layers.
- **RESET TO AUTO:** clears the `ij-layers` localStorage key and re-applies the CURRENT
  device tier's defaults live (no reload needed).
- **Live fps:** reuses the existing `cosmos:perf:req`/`cosmos:perf` event pair `?perf=1`'s HUD
  already established — no new perf-telemetry plumbing.
- **URL override chip:** shown whenever `?layers=` is present.
- **Focus/a11y:** `role="dialog"`, `aria-modal`, focused on mount / restored on unmount
  (`moveFocusTo`/`restoreFocusTo`), Tab/Shift+Tab trapped inside (`trapFocus`) — the exact
  same `focus-utils.ts` trio `CollectorCard.tsx` established as this repo's real-modal
  pattern, reused rather than re-invented.
- **Reduced motion:** no per-component check needed — the entry animation
  (`animate-[ij-cardin_...]`, the same class `CollectorCard`/`SectionOverlay` use) is already
  covered by `global.css`'s universal `@media (prefers-reduced-motion: reduce)` rule that
  clamps every animation/transition to near-zero duration site-wide.
- **No-WebGL:** the HUD's `RENDER ▸` button only renders when `onOpenRenderConsole` is passed,
  which `SpaceScene.tsx` only does when `engineKind === "babylon"` — absent on the archived
  WebGL1 path and absent entirely when no engine mounted (matches "the control is absent,
  nothing to configure").

Wired into `SpaceScene.tsx`: new `renderConsoleOpen` field (`types.ts`), an escape-stack entry
(second priority, after `cardId`), rendered alongside `SectionOverlay`.

**13 new unit tests** (`render-console.test.tsx`, RTL against a stubbed `<babylon-scene>`
element with mocked `sceneStats`/`setLayers`): every layer label renders, the device-tier chip
reads from `sceneStats`, not-yet-implemented rows are disabled with their explanatory text,
toggling a checkbox/number input calls `setLayers` with exactly that id, each preset button's
`setLayers` call, RESET TO AUTO clears storage and reapplies, the URL-override chip, close via
button/scrim, focus lands in the dialog on mount, and a `cosmos:layers` event from elsewhere
updates the rendered checkboxes.

**Known limitation, recorded not hidden:** no mobile-menu entry point. `RENDER ▸` sits in the
desktop-only (`md:block`) HUD cluster, same as `DATA & LICENSES ▸`'s own desktop button — but
credits ALSO has a Header.astro mobile-dropdown menuitem (`space-scene.spec.ts`'s "mobile
menu: Data & Licenses" test), and the Render Console does not yet have that second entry
point. The delivery plan's own spec named only "a RENDER ▸ control in the HUD cluster near
DATA & LICENSES," so this isn't a missed requirement, but a mobile visitor has no way to reach
the console today — flagged as a follow-up.

## D9.3 — Budgets

**The boot-critical-download gate already existed** — `bootCriticalDownloadKB: 2900` in
`budgets.config.mjs` and its cross-check unit test (`load-progress.test.ts`, "the real
on-disk sum of BOOT_CRITICAL_ASSETS stays within budgets.config.mjs") had landed alongside
D1.1's instrumentation work, ahead of this phase, with a comment already naming D9.3 as its
consumer. Found stale-in-scope during implementation, recorded rather than redone.

**What D9.3 actually added:** `budgets.config.mjs` gained a new `layerBytes` export — the real
measured byte sizes for every layer with an actual network fetch (`starField`, `bonusStars`,
`sdssField`, `beltVisual`, `planetHires`) — and `render-layers.ts`'s `LAYERS[].assetBytes` now
reads FROM this export instead of restating its own copy of the same numbers, closing the
"single source of truth" requirement the implementation plan named. **5 new unit tests**
assert both directions: `LAYERS` matches `layerBytes` exactly, AND `layerBytes` matches the
real files on disk (`stars-hip.png`+`deep.png`, the 4 bonus chunks, `sdss18.png`,
`asteroids-dr3.png`) via `statSync` — the same discipline the pre-existing boot-critical test
already applies to `BOOT_CRITICAL_ASSETS`, extended to cover the panel's own numbers.

**Deliberate budget raise, this pass:** `totalJsGz` 1215 → 1225 KB. TR-111 (D7) had already
flagged the margin as tight (~7 KB) after the new SDSS-decode worker chunk; D9's new
`render-layers.ts`, `RenderConsole.tsx`, and the engine's `setLayers()` surface measured
**1210.7 KB**, 4.3 KB under the OLD ceiling but with no room left for D9.4's remaining work —
raised ahead of the wire rather than at it, per this file's own "raise deliberately, with a
why, in the same commit" rule. ~14 KB headroom restored.

## D9.4 — Defaults calibration

**Recorded as owner-pending, not silently skipped.** D9.4 depends on D0.3 (the owner
real-device pass), which has not run. What shipped instead: every `defaultByTier` value in
`render-layers.ts` is the CURRENT shipped behaviour made visible and adjustable —

- Every layer that already ships unconditionally on every tier today (`bonus-stars`,
  `sdss-field`, `belt-visual`, `nebula-volumes`, `gd1-trail`, `constellations`,
  `milky-way-band`) defaults to `true` on `full`/`balanced`/`lite` alike, because that is
  literally what ships today ("ideal state first, desktop baseline" — PF-10 TR-067).
- `belt-physics` mirrors `QUALITY_BUDGETS[tier].asteroids` (48/32/20) EXACTLY — asserted by a
  unit test, not eyeballed.
- `planet-hires` mirrors `QUALITY_BUDGETS[tier].planetTexture === "ultra-progressive"` EXACTLY
  — also asserted.
- `gaia-tiny` defaults off everywhere, because it doesn't exist yet.

This is a real default — a visitor gets a coherent, working preset system today — just not a
newly-measured one. `render-layers.ts`'s own header comment and a new ADR-0010 addendum (dated
2026-07-29) both state this explicitly, so it is never mistaken for a calibration result.
Re-run D9.4 once D0.3 lands.

## Known limitations / follow-ups

- **E2E unrun** — see above.
- **`bonus-stars` is not independently toggleable** — merged into the base star mesh for one
  draw call. Separating it needs the base field kept cached and a rebuild-without-merge path
  on disable; a real structural change, not attempted this pass.
- **`gaia-tiny` is a registry placeholder** — D8 has not shipped the OctreeLoader reader or the
  chunked asset pipeline this layer needs. The mechanism (chunk-prefix-style count value) is
  ready; the data is not.
- **No mobile-menu entry point for the console** — see D9.2's own note above.
- **`planet-hires`'s toggle only affects the NEXT body dressed**, not an already-loaded ultra
  texture on the body currently on screen.
- **D9.4's defaults are not real-device calibrated** — see that section above; re-run once
  D0.3 lands.
- **Heap/VRAM release is asserted structurally (dispose + guard reset), not measured** — the
  phase's own exit criterion ("disable actually releases, heap/VRAM measured") needs the
  owner's real-device pass, same as D7's own unmet measurement obligation (TR-111).
- D8 (Gaia DR3 Tiny) remains, and now has its layer mechanism ready to build on.
