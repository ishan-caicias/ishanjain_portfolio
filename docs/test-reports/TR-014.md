   - Both layers are **LFS-pointer-aware**: on checkouts without materialized LFS (CI checks out

4. **Checkpoint relocation:** the interactive HTML report moved to

## Plan Deviation (recorded, per the P0 measurement gate)

The plan's baseline ("quantize if budget requires") was measured and found insufficient:
quantized geometry alone was 1.036 MiB — over both tier budgets before textures. Adopted at the
gate the plan defined for exactly this case:

- **`EXT_meshopt_compression` (level high) for both tiers.** Full-quality geometry beats a 55%
  simplified mesh shipped to dodge a decoder; the P1 loader takes the self-contained
  `meshopt_decoder` (~35 KB) plus ~20 lines of decode.
- **1K tier additionally simplified (ratio 0.5 → 18,600 verts).** Its purpose is minimal
  transfer for data-saver/low-GPU contexts, and the P4 quality selector lets visitors opt up.

Final sizes land within 3% of the rolled-back Codex implementation's claimed numbers
(0.412 vs 0.42 MiB) — independent confirmation those were meshopt-derived.

Dependency note: `sharp` had to be pinned to `0.34.5` — the top-level 0.35.3 clashed with the
copy nested under `@gltf-transform/functions → ndarray-pixels` (two libvips DLLs, same module
name, one process → `ERR_DLOPEN_FAILED`). Single deduped version across the tree resolves it.

## Known Limitations

- CI runs the new tests in pointer-skip mode (no `lfs: true` on checkout) — binary integrity is
  validated on dev machines only, consistent with the repo's existing images. Enabling LFS on CI
  is a HARDEN-phase decision (bandwidth-quota trade-off) noted for P5.
- Netlify deploy behaviour for LFS-stored GLBs is assumed to match the existing LFS images;
  first production deploy after P1 should confirm the served GLB is binary, not a pointer.
- Visual quality of the simplified 1K mesh is unreviewable until P1 renders it — flagged as the
  first thing to eyeball at the P1 gate.
