## `CLAUDE.md` — design rationale

Authored against [Anthropic's Claude Code best practices](https://code.claude.com/docs/en/best-practices)
and HumanLayer's `CLAUDE.md` guidance. The governing constraints from those sources: the file
loads into **every** session, so bloat causes rules to be ignored; exclude "information that
changes frequently"; prefer progressive disclosure to inlining.

The load-bearing decision, and the direct answer to "don't let this drift again":

> **`CLAUDE.md` contains zero volatile facts.** No test counts, no version numbers, no phase
> status. Those are precisely what drifted. It opens with an Orientation table routing every
> volatile question to its authoritative index, and the instruction: _never quote a test count,
> version, or phase status from memory or from this file._

A document that cannot go stale does not need maintaining. What remains is 23 durable
non-negotiables (each traced to the TR that earned it), the canonical commands, the engine
seam, measurement discipline, and a **Documentation contract** table mapping each kind of
change to the doc it obliges.

## The drift gate — `npm run docs:check`

`scripts/check-docs-drift.mjs`. Advisory rules did not prevent this drift, so the mechanical
subset is now enforced. Five checks, each corresponding to a real instance found above:

1. Engine default parsed from `engine-select.ts`; current-state docs must not name the other
   engine as default, and must mention the actual one.
2. Each ADR's `**Status:**` header must match its index row.
3. Every TR on disk has an index row, and every indexed TR exists.
4. Relative links resolve — **in current-state docs only**; dated records are exempt by design
   (10 of the 11 first-run findings were historical analyses whose links point at artefacts
   that were planned but never landed; repointing them would rewrite history).
5. `overview.md` must mention `babylon-scene`, `space-engine`, and `engine-select`.

**The instrument was tested, not assumed** (TR-032's lesson): an unindexed `TR-099.md` and a
`babylon-scene` removal from `overview.md` were both injected and both correctly caught, then
reverted. It runs as a **step in the existing `lint` job**, not a new job — adding a job would
have invalidated the branch-protection ruleset's required status-check names (TR-034).

**Honest limit, printed by the tool itself:** these are mechanical checks. A clean run does not
mean the prose is accurate. It catches contradiction, staleness of indexes, and broken links —
not a paragraph that quietly describes the wrong system.
