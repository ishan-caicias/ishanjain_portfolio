## Bugs Found and Fixed (not just handoff items)

1. **Hamburger `<label>` had no accessible role.** A `<label>`'s implicit ARIA role is not
   "button" even with `aria-label` set - confirmed empirically (Playwright's `getByRole("button",
...)` couldn't locate it at all). This affected the _pre-existing_ menu button too, not just
   this pass's new markup. Fixed with `role="button"` + `tabindex="0"` + a keydown handler for
   Enter/Space (labels don't get native keyboard activation the way real `<button>`s do).
2. **A `group-has-[:checked]:opacity-100`/`scale-100` transition appeared stuck at its starting
   value during manual live-preview testing**, while `pointer-events`/`display` variants on the
   same elements reacted correctly. Root cause: the preview tab runs backgrounded
   (`document.hidden === true`), and CSS transitions tied to the compositor are suspended for
   hidden tabs (browser power-saving), while discrete, non-animated property changes apply
   instantly regardless. Confirmed via `.matches()` that the selector genuinely matches, and via
   an isolated reproduction that resolves correctly after a real 1s delay when the tab is
   backgrounded but the underlying page is otherwise identical. This is the same documented
   testing-harness artifact as TR-001/002/003 (`document.hidden` throttling `requestAnimationFrame`)
   applied to CSS transitions instead - not a functional bug, confirmed via Playwright's
   real (foregrounded, non-throttled) test browser, where all 7 new mobile tests pass.
