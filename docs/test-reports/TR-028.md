## Why this TR is partial

The B1 exit criterion is _"parity scene measured on real desktop + mid Android + iPhone; ADR
written; go/no-go recorded."_ Two of those require the owner's hardware: headless CI renders WebGL
via SwiftShader (CPU) and has no WebGPU, so it cannot produce representative fps or exercise the
WebGPU path. This session completed and verified everything else; the fps/startup measurement and
the resulting ADR are handed to the owner via
[the B1 gate procedure](../validation-checklist/2026-07-18-pf09-b1-gate-measurement.md). No fps
proxy is reported here because a SwiftShader number would be actively misleading for the gate.

## What changed

1. **Tree-shaken Babylon** — the B0 barrel import (`@babylonjs/core`) is replaced with subpath
   imports (`@babylonjs/core/Engines/engine`, `…/scene`, `…/Maths/math.*`, `…/Meshes/*`,
   `…/Materials/shaderMaterial`, …). **WebGPU** is loaded via a further dynamic import only when
   `navigator.gpu` exists, with a **WebGL2 fallback** (`Engine`).
2. **Fps-critical star cloud** — a representative **168,959-point** cloud
   ([star-field.ts](../../src/lib/star-field.ts), pure + seeded) rendered as a custom
   `ShaderMaterial` point cloud (photometric-ish colour ramp + soft point sprite). This is the
   real performance driver the gate turns on. The streaming catalog + full photometric/relativistic
   port is B1-continued/B2.
3. **Backend reporting** — the scene records `webgpu`/`webgl2` on the element and in the badge, so
   the owner's measurement records which backend actually ran.

## Notes / B1-continued (before or alongside the gate)

- The point shader is **GLSL** (WebGL2). Babylon 8 WebGPU wants **WGSL** — if a device unexpectedly
  falls back to WEBGL2, port the two shaders to WGSL before a true WebGPU reading.
- The spike cloud is **procedural**, so its fps is an **upper bound** on the full catalog scene —
  treat a marginal device pass as a fail.
- No ADR written: ADR-0002 is **not** superseded until the gate reads GO on real devices.
