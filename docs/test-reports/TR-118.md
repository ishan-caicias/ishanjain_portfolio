# TR-118 — Fix: raw `[[TODO]]` authoring marker leaking into collector-card field notes

**Date:** 2026-09-02
**Slice:** the incidental content-pipeline defect TR-117 flagged (spawned as a follow-up task)
during its manual regression pass — not part of PF-11's own scope, unrelated to that session's
changes.

## Defect

`CollectorCard.tsx`'s FIELD NOTE section rendered `e.f` verbatim. Several bulk-generated
catalog files (`celestial-nbg.js`, `celestial-gd1.js`, `celestial-ngc2000.js`,
`celestial-clusters.js`) ship entries with no content pass yet, carrying an internal
authoring marker as `f` — an explicit `[[TODO: ...]]` placeholder rather than fabricated
content, per TR-061's honesty convention (documented in `docs/datasets/star_clusters_hall_of_fame.md`).
That marker was never filtered before display, so visitors landing on any of the ~2,300+
undocumented bodies (background galaxies, GD-1 stream stars, NGC2000/cluster entries) saw the
raw double-bracket text as their field note. Three distinct wordings exist across the flagged
files (confirmed by reading each, not assumed identical). `celestial-clusters.js` additionally
ships some entries with the same marker inside `lo` (sky-lore) as `[["", "[[TODO: ...]]"]]`
rather than `lo: null` — the equivalent leak in the SKY LORE section, found while checking all
bulk-generated files per the follow-up task's own instruction, not in the original report.

## Fix

Per TR-061's convention (no invented flavour text to paper over a gap), the fix omits the
section rather than writing a generic sentence: two new pure helpers in `src/lib/spaceHelpers.ts`,
`resolveFieldNote(e)` (returns `null` for a TODO-marker `f`, via a regex matching any `[[TODO:`
prefix rather than an exact-string list — future wordings are covered without a code change) and
`resolveLore(e)` (filters TODO-marker tuples out of `e.lo`). `CollectorCard.tsx` now conditionally
renders the FIELD NOTE block only when `resolveFieldNote` returns non-null, and builds its lore
list from `resolveLore` instead of mapping `e.lo` directly. `ArrivalVista.tsx` does not render
either field — confirmed by grep, not assumed — so no change was needed there.

## Verification

- `tests/unit/space-card-visual-fallback.test.ts` — 6 new cases: a real field note passes
  through unchanged; all 3 real marker wordings (plus a synthetic future one) are omitted; an
  empty string is also omitted; `resolveLore` keeps real lore and drops TODO-marker tuples;
  `resolveLore` handles `lo: null`.
- `npx vitest run tests/unit/space-card-visual-fallback.test.ts` — 20/20 pass.
- `npm run test -- --run` — full suite, 949/949 pass (54 files), up from TR-117's 944.
- `npx eslint` + `npx prettier --check` on all touched files — clean.
- `npx astro check` — 175 files, 0 errors/warnings/hints.
- **Manual regression, live in the browser (`astro dev`, not asserted):** travelled to
  `nbg-a0554-07` (the exact repro case from the original report), opened its collector card.
  Before: `FIELD NOTE` heading followed by the raw `[[TODO: content pass — PF-10 C1 bulk
dataset, no per-object dossier authored]]` string. After: the card goes directly from
  `LINEAR DIAMETER` to the share/holo control — no FIELD NOTE section, no raw marker text.
  Zero console errors across the session.
