# TR-103 — Planet-class arrival standoff + user zoom control (Vega SHOT-BRIEF)

**Date:** 2026-07-25
**Slice:** Owner feedback items #2 (framing) and #3 (zoom feature), designed by
[Vega's SHOT-BRIEF](#vega-shot-brief-summary) below, implemented by Procyon.
**Predecessor:** [TR-102](TR-102.md) (arrival camera aim + classic-view scroll fix)

## What this pass is

TR-102 fixed the arrival camera's _orientation_ (it now correctly points at the arrived body).
This pass addresses the remaining half of owner item #2 — the arrival _distance_ — plus item
#3, a new user-controllable zoom feature, both per a Vega SHOT-BRIEF requested specifically
because `ARRIVE_STANDOFF` turned out to be coupled to two other systems (the ascent cinematic
and the R16 home orbit), making a naive constant change unsafe.

## Vega SHOT-BRIEF summary

Full brief delivered in chat; key numbers reproduced here for the record:

- At the old universal `ARRIVE_STANDOFF` (38 units) from a `PLANET_SPHERE_RADIUS`=26 sphere,
  the sphere subtended `2·asin(26/38) ≈ 86.3°` — wider than the 70° base FOV, i.e. edge-to-edge
  with zero sky visible.
- New, decoupled `PLANET_ARRIVE_STANDOFF = 80` targets `2·asin(26/80) ≈ 37.7°`, roughly half
  the FOV — the classic reveal ratio.
- Zoom = **dolly** (distance), never FOV — FOV changes beyond ±3-6% read as a lens change, not
  a zoom (motion-language.md's own FOV-breathing ceiling).
- Zoom is **orthogonal to free-look**: a fixed bearing (direction from target to camera, set at
  arrival) that free-look's yaw/pitch changes never touch; zoom only changes distance along
  that fixed bearing.
- Bounds: planet-class floor = `PLANET_SPHERE_RADIUS + margin` (absolute, near-clip-safe);
  point-like (DSO/star/field object/home-orbit) floor/ceiling = a multiple of resting distance
  (nothing physical to collide with). Ceiling both cases = `3× the arrival distance`.
- Curve: critically-damped-feeling exponential ease (~150-250ms settle), snapping instantly
  under reduced motion (direct manipulation, not an ambient move — matches this repo's existing
  `_reduced` convention for driven camera values).

## Implementation

**`ship-dynamics.ts`** (pure, unit-tested): new `PLANET_ARRIVE_STANDOFF` (80),
`PLANET_SPHERE_RADIUS_FOR_ZOOM`/`PLANET_ZOOM_NEAR_MARGIN` (literal duplicate of
`planet-sphere.ts`'s `PLANET_SPHERE_RADIUS`, same reasoning as this file's other duplicated
constants — kept import-free/pure, agreement enforced by a live test), `ZOOM_MIN_MULT`/
`ZOOM_MAX_MULT`/`ZOOM_STEP`/`ZOOM_LAMBDA`, and two new pure functions: `clampZoomDistance`
(bounds logic) and `dampScalar` (the non-wrap-aware sibling of the existing `dampAngle`, for
plain scalar values with no periodicity).

**`babylon-engine.ts`**:

- `travelTo` picks `PLANET_ARRIVE_STANDOFF` for `planet`/`moon`/`dwarf`-typed bodies,
  `ARRIVE_STANDOFF` (unchanged) for everything else (stars, DSOs, stations, `fs-` field
  objects).
- New fields: `_parkedTargetPos` (arrival target's world position), `_camBearing` (fixed unit
  vector from target to camera, set at arrival, never touched by free-look), `_zoomDist`/
  `_zoomTargetDist` (current/target standoff, eased each idle frame), `_zoomRestDist` (the
  fixed reference this arrival actually used, for bounds — kept separate from
  `_zoomTargetDist`, which _does_ change with every zoom step).
- Arrival (`_tickWarp`'s `k>=1` branch): extends TR-102's aim-fix block to also set
  `_camBearing` (the negation of the already-computed aim direction — no redundant
  recomputation), `_parkedTargetPos`, and reset zoom to the real arrival distance. `w.home`
  resets zoom to `HOME_ORBIT_RADIUS` with no fixed bearing (the orbit's own position update
  already recomputes bearing every frame by design).
- Idle branch: eases `_zoomDist` toward `_zoomTargetDist` every frame (snapped instantly under
  `_reduced`); home-orbit case feeds the eased value straight into `homeOrbitPosition`'s
  existing (already-optional) radius parameter — its pure scale-by-radius construction keeps
  the 90° phase invariant exactly regardless of radius, so zoom can never disturb R16's
  terminator-hold; non-orbit case repositions `this.cam` from `_parkedTargetPos +
_camBearing·_zoomDist` — a no-op every frame zoom hasn't been touched, since `_zoomDist`
  already equals the position `this.cam` was already holding.
- New `_adjustZoom(steps)`: a safe no-op unless genuinely parked; multiplicative step applied to
  the _target_ distance (the spring, not this method, does the actual easing), then clamped.
- Input: a new `wheel` listener on the canvas (`_bindPointer`, `passive: false` only so
  `preventDefault` can suppress page/section scroll — but only while actually parked, so
  scrolling is never blocked for no reason); `+`/`=` and `-`/`_` added to `_bindKeys`'s existing
  keydown handler. HUD hint line and the engine element's `aria-label` both updated to mention
  zoom.

**Not implemented this pass, named honestly:** an on-screen zoom affordance for touch devices
(Vega's brief calls this "worth adding specifically for touch" — a secondary enhancement for
one device class, not core scope; wheel + keyboard covers the owner's "or" between three
input options).

## New test coverage

**Unit** (`ship-dynamics.test.ts` +6, `planet-sphere.test.ts` +2): `clampZoomDistance`'s two
floor policies (absolute near-clip margin vs. multiplicative), ceiling behavior, pass-through
for in-bounds values; `dampScalar`'s convergence (including a zero-dt no-op guard); the
`PLANET_SPHERE_RADIUS_FOR_ZOOM`/`PLANET_SPHERE_RADIUS` cross-module agreement (same pattern as
the existing `HOME_ORBIT_RADIUS`/`ARRIVE_STANDOFF` test); `PLANET_ARRIVE_STANDOFF`'s angular
target sanity check.

**E2E** (new `tests/e2e/camera-zoom.spec.ts`, 5 tests, drives the real wheel/keyboard input
paths per CLAUDE.md #18 rather than calling `_adjustZoom` directly):

1. Mars (planet-class) arrives measurably farther back than Sirius (star-class) — proves the
   type-based branch in `travelTo`.
2. Real `WheelEvent` dispatch zooms out, then back in, via the actual listener.
3. Zoom clamps at both bounds under an aggressive single large delta — uses `expect.poll` for
   the eased convergence rather than a fixed wall-clock wait, since the spring's convergence
   depends on accumulated in-engine `dt` (itself capped per frame at `SHIP_MAX_DT`=50ms), which
   doesn't track wall-clock time 1:1 under this environment's slower/contended render rate
   (same class of timing sensitivity this repo's own TR-032/033/081/094/096/097 document).
4. Real `KeyboardEvent` (`page.keyboard.press`) zooms the same way, via `_bindKeys`'s actual
   listener (element focused first, matching the existing arrow-key/Enter/H requirement).
5. Zooming doesn't change orientation — Mars's projected screen position stays within a few
   pixels of canvas centre after zooming out, proving zoom is a pure dolly along the fixed
   bearing, not an orbit. (Reads `_projectBody`'s `sx`/`sy` output directly rather than
   `_hoverId`, which has a pre-existing, unrelated planet-sphere self-occlusion quirk in
   `_pick` — the sphere's near surface is always closer than the catalog point it represents,
   so the occlusion check meant for _other_ bodies behind the sphere incidentally nulls the
   arrived body's own point too. Not introduced by this feature; not fixed here — out of
   scope, flagged as a pre-existing corner case no earlier test had touched, since every
   existing hover-after-arrival test deliberately uses a star target specifically to avoid it.)

**A real process mistake caught before it mattered:** the first E2E run of this new spec (all 5
tests) failed with every arrival distance reading ~38 instead of ~80 — not a product bug, but
`dist/` being stale (the zoom code was written and unit-tested, but `npm run build` wasn't
re-run before launching Playwright, so it served the pre-zoom build). Caught by the readings
being suspiciously identical to the _old_ behavior rather than assumed to be a real defect;
rebuilding and rerunning resolved it immediately.

  — same Browser-pane backgrounded-tab constraint documented since TR-095. What specifically
  needs eyes: does the 80-unit planet default actually read as "arrived, with context" or as

  step size feel comparable to one wheel click; does zoom during the home orbit feel consistent
  with zoom at a regular arrival.

  arrived planet's own catalog point can be nulled by the occlusion check meant for background
  bodies) is pre-existing, not introduced here, and not fixed here — flagged for whoever next
  touches `_pick`.
