## Two decisions worth recording

**1. `(type, colour)` packed into one float rather than a third attribute.**
B2 step 1's saving (−5.2 MiB) is load-bearing; a per-vertex type attribute would hand back ~2.7 MiB
of it. Type is 0–7 and colour is a byte, so `type + ci/256` fits one f32 with three orders of
precision headroom, recovered via `floor()`/`fract()`.

Dividing by **256, not 255** is deliberate and tested: `ci = 255` would otherwise pack to exactly
`type + 1.0`, and `floor()` would report the next object class for **every reddest star in the
catalog** — an off-by-one that bites at one end of the range only, which a spot check would miss.

**2. Quad geometry floored at 1.5 px while alpha stays photometric.**
The live engine writes `px` to `gl_PointSize`, which WebGPU has no equivalent for (TR-029) — hence
quads. A 1 px quad can fall between pixel centres and vanish, so faint stars would flicker as the
camera drifts, where a 1 px point sprite always rasterises. The **geometric** extent is therefore
floored; **visibility** remains driven by `flux`. This is the density fix, not a cosmetic dimming
pass: the magnitude distribution is steeply faint-weighted, so most stars land at ~1 px and alpha
0.10 — present, but only a few thousand resolvable, which is what makes the live sky read correctly.

Billboards are offset in **clip** space (`corner · px · clip.w / uViewport`) rather than view space,
so the mapping is exact under any projection and independent of handedness — Babylon is
left-handed, the live engine is not.

## The new E2E assertion caught a real defect it was written to catch

`loadChunkRGB` read `bmp.width` **after** `bmp.close()`, which zeroes it — so the catalog decoded to
zero records, threw, and silently fell back to the procedural placeholder.

**The pixel proof passed anyway**, because the fallback draws a perfectly good sky. Without the
`starSource === "catalog"` assertion this would have shipped looking like success, and TR-037's
defect would have returned invisibly. Fixed by capturing the dimensions before `close()`.

That is the whole reason the fallback reports its provenance rather than just working: a downgrade
that cannot be distinguished from success is worse than no fallback.

## Honest limits

- ~~The WGSL twin is still unvalidated on real WebGPU hardware.~~ **Corrected in
  [TR-039](TR-039.md): wrong on two counts.** The WGSL twin was already proven on real hardware
  before this report was written — [ADR-0003](../adr/0003-babylon-webgpu-renderer-adoption.md)
  condition 2 was discharged 2026-07-19 on a physical Android, and I failed to cross-check it. And
  "Playwright's chromium has no WebGPU adapter" was imprecise: the bundled Testing-build binary
  genuinely can't get one, but `channel: "chrome"` (the real installed browser) does, with a real
  adapter, no flags needed — TR-039 adds an automated test using it. What remains true: **CI**
  specifically has no adapter (GitHub's GPU-less runners, bundled-chromium-only install), which is
  a real, narrower limit than what was originally written here.
- **The visual density improvement itself is not asserted by a test.** CI proves the real catalog
  loads and that the photometric mapping collapses faint magnitudes to the alpha floor. Whether the
  sky now _looks_ right against the live engine is an owner observation on a real screen — the same
  loop that produced TR-037.
- **Not ported (deliberate, sequenced):** relativistic aberration + Doppler need the flight model's
  velocity (B2 steps 3–5); tier-gated halo amplitude runs at top tier until B5 formalises tiers.
